### 2. Layer 2 Risks

* **Outbox-only risk cannot block fraud pre-capture:** If Layer 2 only reads outbox events, `provider.createCharge()` (`files/commerce-src/payments/lipay-plugin.ts:651`) has already moved money. **Fix (`v1`, L4, S):** (a) Add a synchronous `RiskEvaluatorPort.evaluatePreCharge` gate in `charge()` (≤150ms timeout, explicit fail-open/closed policy) returning `"allow" | "block" | "manual_capture"`. (b) For elevated risk, authorize with `captureMode: "manual"` (`requires_capture`); Layer 2 evaluates the outbox event asynchronously and calls `PaymentsPort.capture()` or `void()`—never writing money tables directly.
* **Location & graph privacy (`v1`, Layer 2 lot, S):** Raw GPS/IPs and cleartext emails/fingerprints in `GeoPort`/`FraudGraphPort` create GDPR liability. Store coarse H3/geohash cells or distance buckets in `RiskSignalStore`, and HMAC-SHA256 (with an install pepper) shared nodes (email, IP, device, card fingerprint) in `FraudGraphPort`.
* **Drop per-DB Layer 2 adapters (`v1` portable / `later` PG accelerator, M):** `@jini-ai/db` mandates one Kysely query body across dialects ([port.ts](file:///Users/la/Programming/tovu-integration-clones/jini-int/packages/db/src/kernel/port.ts#L7) `packages/db/src/kernel/port.ts:7`) and 4 portable column affinities ([dialect.ts](file:///Users/la/Programming/tovu-integration-clones/jini-int/packages/db/src/kernel/dialect.ts#L171) `packages/db/src/kernel/dialect.ts:171`). SQLite R*Tree isn't universally compiled in, and PostGIS isn't on every PGlite/Postgres install. Ship **one portable adapter** (indexed bounding-box `REAL` columns + TS Haversine; flat `fraud_edges` table + 2-hop SQL join), with PostGIS as an opt-in accelerator later.
