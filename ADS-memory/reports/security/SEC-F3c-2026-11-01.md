## Final rule table

Here, “match” means a valid HTTP(S) URL whose origin equals either the canonical site origin or actual serving origin.

| Method | Origin | Referer | Decision with absent or `same-origin` Fetch Metadata |
|---|---|---|---|
| Any | Present and matching | Any/absent | Allow |
| Any | Present but invalid, empty or foreign | Any/absent | Refuse |
| GET/HEAD | Absent | Matching origin | Allow |
| GET/HEAD | Absent | Foreign, invalid or absent | Refuse |
| Every other method | Absent | Any/absent | Refuse |

For **every method**, present `Sec-Fetch-Site` must be exactly `same-origin`. Cross-site, same-site, none and empty values veto otherwise valid headers. Absent metadata never independently grants permission. A present Origin always wins over Referer, including when invalid.
