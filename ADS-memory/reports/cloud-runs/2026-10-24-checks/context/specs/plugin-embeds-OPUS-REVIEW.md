## Confirmed (keep)
- The registry is the extension point: `J/cms/src/widgets/resolver-service.ts:1285` (`satisfies Record<PageEmbedType,…>`), with types in `J/cms/src/widgets/page-embed-types.ts` (`PAGE_EMBED_TYPES`). - `embedMarkerSnippet` handles identifiers only (`marker.ts:688-692`).

## Binding changes
1. **Placeholder contract.** `{"type":"plugin","plugin":"<manifest id>","component":"<name>","version":N,"props":{…}}`. A missing `version` means 1. Unknown keys are ignored. Extend `toEmbedRef` (`J/cms/src/widgets/html/html-embeds.ts:217`) to key plugin refs `plugin:${occurrence}`, the way gallery refs are keyed already. No new placement-key mechanism.
2. **Fallback, not empty.** This reverses design line 105. An unresolved embed (disabled, missing, unknown component, invalid props, version unsupported, static fallback) renders `withInnerContentFinal({marker, inner: marker.inner})` (`marker.ts:750`): the wrapper and the author's fallback HTML stay, and only `data-embed-config` is removed. This needs a `plugin` arm in `substituteHtmlEmbeds` (`html-embeds.ts:510`, the same pattern as the media arm), because Tovu's `resolve` callback only receives `ref`. `resolvePageBodyEmbed` (`T/server/inbound/public-http/http/site/render.ts:1919-1931`) must never swap a plugin ref for `HTML_EMBED_PLACEHOLDER_IR` (:1846). The page never fails.
3. **Wrapper always kept, server-stamped.** A plugin marker is always wrapper-preserving, so the author's `class`, `style`, `id`, and `aria-*` survive (precedent: `html-embeds.ts` header, 2026-09-16 owner rule). The host sets `data-plugin`, `data-component`, `data-embed-v`, and `data-consent-category` on the wrapper, **overwriting** any author-typed values. Ids only, no PII. The stamps go on the host wrapper **after** fragment validation, never inside the template (the validator rejects `data-*`).
4. **Manifest `exports` block.** Rename the design's `components` to `extensions.<ns>.exports`, keyed by component name. Each entry: `template`; `props` (schema in the existing subset, `J/agent-plugins/src/admin-surfaces/action-schema.ts:12` and `checkAdminSurfaceActionSchema` :47); `consent` (required, one of `CONSENT_CATEGORIES`, `J/cms/src/consent/types.ts:2`); `staticExport` (required, `full`, `link-only`, or `fallback-only`); `version` (integer); optional `minVersion`, `aliases[]`, `hostLinks`, `styles`, `assets`. At plugin level, add optional `renamedFrom[]`. Unknown export keys produce a warning, not an error (same as the `KNOWN_MANIFEST_KEYS` warning at `J/agent-plugins/src/lifecycle/manifest.ts:153`).
5. **Versioning.** A marker renders when `minVersion ≤ marker.version ≤ version`. Outside that range it gets the fallback plus the editor reason "page needs plugin vN" or "contract vN retired".
6. **Renames.** This reverses design line 135 for *declared* renames only. A marker plugin id matching an admitted first-party plugin's `renamedFrom`, or a component matching that export's `aliases`, resolves. Undeclared names stay unresolved: no guessing. Two admitted plugins claiming the same old id get the fallback plus an editor diagnostic.
7. **Props checked at save and render.** Save goes through one chokepoint, `T/features/pages/html-document-store.ts:540` (and the seed at :375), where `normalizeEmbedMarkerQuoting` already runs. Inject a validator there. Props that fail a *known* export's schema reject the save with a typed error (the assistant tool error and the editor message come from it). An unknown or disabled plugin saves, with a warning, because the fallback covers it. At render, invalid props fall back.
8. **JSON-in-attribute.** Add `embedMarkerSnippetFromConfig({config})` next to `embedMarkerSnippet`. It is `JSON.stringify` plus the existing private `toSingleQuotedValue` (`marker.ts:455`, which escapes `'` and `&`). The editor and the assistant both use it. Do not write a second escaper.
9. **Theme CSS (owner addition).** This replaces design §3's full-button PNG, which can't be themed. The template is plain HTML with stable classes: `plugin-google-login-sign-in-button` on the root, and parts `__mark` and `__label`. Each export may declare one bundled `styles` CSS file, which the host links once in `<head>` through the existing `extraHead` path (`render.ts:3292`) when that export is on the page. The file uses only CSS custom properties (e.g. `--plugin-signin-bg`, `-fg`, `-radius`, `-height`) inside `@layer plugin-exports`, so any theme rule wins without specificity fights. The G mark is a declared asset (PNG, or SVG served with `nosniff` and a sandbox CSP). A `variant` prop is an `enum` of `light`, `dark`, `neutral`. The button text and the G mark are fixed by Google's branding rules. The plugin `SKILL.md` documents the classes, parts, and properties a theme may set.
10. **Host links replace `componentBindings`.** `hostLinks: {"signIn":"member-login:google"}` must name a capability the same plugin `provides` (google-login `plugin.json` already has `"provides":["member-login:google"]`). The host maps it to `MEMBER_OIDC_PATH`'s `/start` (`T/server/inbound/public-http/routes/members/oidc-deps.ts:19`), and only when `listProviders` says the provider is ready; otherwise the fallback renders. v1 has no URL props. Any future URL prop must be local-path-only: a single leading `/`, no `//`, no scheme. `assertSafeUrl` (`server-fragment.ts:8`) is not enough here, because it allows http(s) and so open redirects.
11. **Caching.** Drop the design's blanket `no-store`. v1 output is the same for every visitor (the start route reads cookies on click), so the public 60s directive stays (`T/server/inbound/public-http/routes/site/pages.ts:320`); a plugin disable behaves like any edit. A member-session cookie already forces `private, no-store` (pages.ts:347). Any future export that renders signed-in state must declare it and go through `resolvePerVisitorResponse`.
12. **Static export.** Read the existing `isStaticExportRequest` (`pages.ts:259`) and apply the export's `staticExport` value. google-login is `fallback-only`. Delete the reverse-proxy and backend-detection bullet (design lines 164-170).
13. **Thin CMS port.** Add an optional `pluginExports` port to `ResolveHtmlPageEmbedsDeps` (`resolver-service.ts:355`). When it is absent, every plugin marker falls back. CMS never imports agent-plugins or Tovu. All functions take `(requiredObj, optionalObj = {})` with CCN ≤ 10.

## Cut list
- The new `plugins_list_components` tool. Instead, add `exports[]` (component, version, props schema, consent, availability, ready snippet) to the existing `plugins_list` agent-plugin rows (`T/features/plugin-runtime/agent-tools.ts:206`).
- The `surfaces` field and the admin surface: v1 is public pages only, and the field can come later as a tolerated key.
- Install-time template validation in agent-plugins. agent-plugins has no cms dependency, so this would add a cross-package import. Bundled-only v1 means one Tovu test that renders every bundled export through the validator does the same job.
- New bespoke limits (template, schema-depth, and asset caps). Reuse the fragment 64 KB cap, action-schema `MAX_DEPTH`, and `exceedsAdminSurfacePayloadLimit`.
- The on-demand usage scanner and placement counts. The stamps (#3) are the v1 attribution; counting waits for an analytics consumer.
- Per-request plugin-dependency metadata, `no-store`, and "recheck admission after async prep" (#11).
- The reverse-proxy static scenario (#12), `componentBindings` (#10), and the full-button PNG (#9).
- Keep the rest of design §8's cuts (third-party admission, plugin scripts, template logic, recursion, click telemetry, cross-origin sessions). Lift only "custom CSS", per #9.
