Lesson for any future run: check the dry-run test count against `vitest run` before trusting scores.

## 4. Triaged survivors (a = real test gap, b = equivalent, c = noise). Files with <80 % or ≥10 survivors; 8–15 survivors read per file, rest summarised by mutator. Full lists: `data/part*-survivors.txt`.
**Recurring patterns (explain a large share of all 686 survivors):**
1. **Regex anchor/quantifier mutants (a)** — `^`/`$`/`{n,m}`/negated-class mutations on identifier grammars survive because tests probe only 1–2 good/bad IDs: capability-declarations (CONNECTION_ID, FIELD_NAME, CALLBACK_FIELD_NAME, CONFIG_NAME: 25 of its 30), surface-capabilities (SCOPE_SET_ID, ATTEMPT_ID, SAFE_CODE: ~16), surface-handlers FAILURE_CODE (7), delivery-bindings FORM_ID (5), installed-package-roots (digest `^…$`, folder name), tools/capabilities STATE_KEY, bundled-digests/bundled-source-archive/skill-file-reader. **Write one table-driven test per pattern: leading junk, trailing junk (`"ok\n"`/`"ok!"`), empty, max length and max+1, uppercase/lowercase boundary.**
2. **Module memoisation `if (!instance) { instance = buildModule(ports); instances.set(ports, instance) }` (b/a)** — 4 survivors each in capability-projection, trusted-plugin-files, set-enabled, bundled-source-archive (and likely other `create*Module`s): no test calls `createXModule(samePorts)` twice and asserts identity / single build. One test: `expect(create(ports)).toBe(create(ports))`.
3. **`isENOENT`-style error-code helpers (a)** — node.ts:30 (6 survivors), installed-package-roots.ts:71 (6): tests never throw a non-ENOENT / non-object error, so the "rethrow unknown errors" arm is unproven. Add: reader throws `EACCES` and `"string"` → propagates.
4. **Port-wrapper arrow functions → `() => undefined` (a)** — persistent-state.ts:16–17, tools/capabilities.ts:235–236, tools/projection.ts:137/188: the delegating lambdas (`hostname`, `token`, `monotonicMs`, `sleep`, http.fetch, limiter.check) are never asserted to forward arguments/return values.
5. **`every`→`some` / `sort` removal (a)** — tools/projection.ts:138,149, trusted-plugin-files.ts:89, seed-bundled.ts:313 (`dirs.sort()`), bundled-source-archive.ts:82: tests use single-element or already-ordered inputs.
6. **Boundary `>` → `>=` (a)** — bundled-source-archive.ts:83 & 125, tools/capabilities.ts:106,171, folder-zip-node.ts:20,44, folder-zip.ts:73: no exact-limit and limit+1 cases (e.g. exactly MAX_SOURCE_FILES, exactly maxBytes).
7. **Error object literal `{}` / `ArrowFunction` in thrown-error options (c)** — `new PackagePathViolation({message})` → `{}` etc.: only matter if error text is a contract (it is user-visible; one `toThrow(/escapes the package root/)` per site kills them).

## 7. What Stryker does NOT catch here
- `StringLiteral` mutants excluded → error/warning *messages* are not checked unless tests assert them (Part 0 asserted them for exports.ts only).
- Type checks off (`disableTypeChecks`, no checker plugin): type-invalid mutants are counted as survivors/killed arbitrarily; `compileError` count is 0 by construction, so the score is slightly pessimistic.
- Indirect kills: "killed" = *some* package test failed (whole-package suite runs, ~6–9 tests/mutant under perTest); a file can score well purely through other files' tests (e.g. `exports.ts` via `manifest` tests).
- Equivalent mutants (memoisation, early-return optimisations, `typeof` before a self-rejecting call) were only identified by reading, not proven.
- Untested *inputs* and unimplemented behaviour; async/timing code (`sleep`, TTLs — `INBOX_TTL_MS` arithmetic survives) and real I/O races; the host side (`@jini-ai/plugins`, `core/`, Tovu admin consumers) is outside `mutate`.
- Only vitest code was mutated; Tovu's node:test code still needs `development/scripts/mutation-sweep.mjs`.
- Setup caveat: the 5 s default vitest timeout fails the dry run under instrumentation (wrapper config used 30 s); a few slow tests may time out as "killed" (13 + 7 Timeout mutants counted as killed).
