/* ================================================================================================
   Source Control page — a CONNECTION page (save a personal access token per provider), not git
   integration. See `features/source-control/SourceControl.tsx`'s own header for the scope boundary
   and why this page is its own Operations entry rather than a Deployment tab.
 
   This file draws on the SAME design tokens `styles.css` defines (`--space-*`, `--surface*`,
   `--border*`, `--font-display`, `--text-*`, `--r-*`, `--ok*`) and reuses the app's shared base
   classes (`.card`, `.card-head`, `.card-title`, `.card-lead`, `.field`, `.field-label`,
   `.field-hint`, `.notice`, `.save-error`, `.page`, `.page-header`) — it does not redefine any of
   those. What follows is only what this page adds on top: the icon-plus-heading row, the vertical
   card rhythm, and the provider-row shape — one accordion of three collapsible rows, not-connected
   vs. connected differing only in marker glyph, surface tint, and summary content.
 
   Visually rhymes with `deployment/StaticSiteTab.tsx`'s `.deployment-step`/`.deployment-step-done`
   numbered-step rows (same bordered-surface-vs-quiet-surface contrast, same disclosure idiom for
   the connected state) on purpose — the brief for this page asked the two credential surfaces to
   "read as one system." It is a deliberate visual rhyme, not shared code: this page owns no CSS or
   component import from `features/deployment/`, since that feature was being built concurrently by
   a different agent in the same session. The one deliberate DIFFERENCE from that pattern: no
   numbered "1"/"2" step markers here. Those numbers on the Static Site tab encode a two-step
   SEQUENCE within one provider's flow (connect a credential, then choose where to publish this
   export). This page's three rows are independent and parallel, not sequential — GitHub, GitLab,
   and Bitbucket are not steps of each other — so each row gets a plain circular marker instead,
   filled with a checkmark once connected, never a number.
 
   `.source-control-tab` (2026-08-16, renamed from `.source-control-page`): the page shell moved to
   `SourceControl.tsx`'s own `.page`/`.page-header` + `TabBar`, mirroring `Deployment.tsx` — see that
   file's header for why. This class is now the PER-TAB wrapper `ProvidersTab.tsx` renders inside
   that shell, the exact same role `.deployment-tab` plays for each of Deployment's own tabs (same
   `display: flex; flex-direction: column; gap` rule, kept as its own class rather than merged into
   `.deployment-tab` since this page owns no CSS import from `features/deployment/` — see this file's
   own header above for why that boundary is deliberate).
 
   ## Second density pass (2026-08-16) — every row is now `<details>`, not just the connected one
 
   `ProvidersTab.tsx`'s own header records why: three simultaneously-open forms read as a wall of
   text, twice reported. `.source-control-row-head`/`.source-control-row-headings`/
   `.source-control-row-subtitle` are removed here — they only ever styled the old always-open,
   plain-`<div>` not-connected row, which no longer exists. `.source-control-row-summary` (below) now
   serves BOTH states, so its sibling `[open]` rules generalize from `.source-control-row-done[open]`
   to plain `.source-control-row[open]` — every row carries the base class regardless of connected
   state, only `-done` differs.
   ================================================================================================ */

/* Tightened to --space-2 (2026-08-16): now that every row is a collapsible `<details>` (see

/* ---- One provider row --------------------------------------------------------------------- */
 
/* The base row shell, shared by both states — a real bordered surface (not a tinted/accented one —
   this is a primary action row, not a recommendation or a settled fact), mirroring `.deployment-step`'s
   own reasoning. The connected variant quiets it down further via `.source-control-row-done` below.
 
   Internal `gap` at --space-3 (tightened from --space-4, 2026-08-16, owner-flagged, kept through the
   later accordion pass below): GitHub, GitLab, and Bitbucket are still independent and parallel, not
   a Deployment-style single tab picker — see `ProvidersTab.tsx`'s own header — they just now ALSO
   collapse like one, via a native exclusive `<details>` group rather than a tab bar, since this page
   never grew a per-provider tab bar of its own. `padding` stays at --space-4 — that is breathing room
   around the row's own border, not stacking between its internal blocks, and shrinking it would
   cramp the row rather than shorten the page. */

  padding: var(--space-4); background: var(--surface); border: 1px solid var(--border-strong); border-radius: var(--r-md);
}
/* The not-yet-connected marker — an empty ring, no glyph inside: there is nothing to report yet,

/* Every row's `<summary>` — marker, then settled-fact-or-heading text, then the EXPAND affordance
   (`.source-control-row-summary-expand`) pinned to the far end. Shared by both the not-connected and
   connected states since 2026-08-16 (`ProvidersTab.tsx`'s own header) — previously only the
   connected row used `<summary>` at all. This is deliberately NOT the "strip the native triangle,
   rely on the row being clickable" treatment the Static Site tab's credential rows originally
   shipped with and were corrected out of (owner-reported: a settled row with no visible affordance

   visible one, not removed outright. */

.source-control-row-summary-text { min-width: 0; flex: 1; }
/* The visible expand affordance. Connected rows pair a text label ("Replace token") with the
   chevron — see `SourceControlRowSummary`'s own doc for why that pairing is required rather than
   the chevron alone. Not-connected rows show the chevron only: their own heading text ("Connect
   GitHub") already states the action, so a second label here would repeat rather than clarify.
   `margin-left: auto` keeps this pinned to the row's far end regardless of how long the summary
   text runs. */
.source-control-row-summary-expand {
  display: inline-flex; align-items: center; gap: var(--space-1); flex-shrink: 0; margin-left: auto;

}
/* The chevron rotates open on `[open]` — CSS-only, no JS state to track since `<details>` already

   plain `.source-control-row[open]` (2026-08-16): every row is a `<details>` now, not just the
   connected one, so both states get the same rotation. */
.source-control-row-summary-expand svg { transition: transform 0.15s ease; }
.source-control-row[open] .source-control-row-summary-expand svg { transform: rotate(180deg); }
.source-control-row[open] .source-control-row-summary { margin-bottom: var(--space-1); }
