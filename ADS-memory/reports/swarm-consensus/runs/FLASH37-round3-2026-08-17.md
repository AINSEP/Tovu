# Round 3 Response: Correcting Build & Tier Invariants Against Shipped Code

---

## 1. Responses to Open Questions

### Question 1: Should `build.source: "compiled"` ever be allowed on non-`static` tiers?
**Position: Permanently Refuted / Static-Only by Construction.**

* **Reasoning:** 
  1. **Separation of Provenance vs. Runtime Engine:** `tier` specifies the *runtime evaluation contract* of the theme within Tovu (e.g., `static` = client-rendered assets served over HTTP; `templated` = server-evaluated safe template AST; `declarative` = JSON UI layout schema). `build.source` describes *authoring provenance* (whether assets were handcrafted or generated by an upstream bundler/compiler).
  2. **Physical Asset Reality:** Any framework compilation (React, Vue, Angular, Svelte, Astro, Solid) produces static HTML documents/fragments, CSS bundles, JS modules, and static media files. At request/serve time, Tovu does not spawn node processes or execute framework SSR runtimes for third-party themes. The server delivers static files and client hydration scripts.
  3. **No Execution Mismatch:** A compiled theme's execution target is strictly the browser/edge static asset pipeline. Allowing `tier: "templated"` or `tier: "declarative"` with `source: "compiled"` would imply Tovu compiles code into server-side template syntax or declarative schemas, which violates the architecture. Therefore, `source: "compiled"` strictly requiring `tier: "static"` is an immutable architectural invariant.

---

### Question 2: Should the generated tree outside `sourceDir` conform to the invariant shape?
**Position: Strongly Agree with Coordinator (Uniform Runtime Invariant).**

* **Reasoning:**
  1. **Zero-Branching Downstream Pipeline:** The runtime server, HTTP routing layer, CDN caching layer, theme validator, preview renderer, and coding agents must interact with a single, predictable layout (`render/`, `css/`, `scripts/`, `assets/`).
  2. **Role of Normalization:** As established in `code-tier-asset-normalizer.ts` (`normalizeBuildOutputDirectory()`, `rewriteBundlerHtml()`), it is the build/normalization step’s responsibility to map bundler output (e.g., Angular `dist/browser/` or Astro `dist/`) into Tovu’s invariant directories.
  3. **Inspection & Security Auditing:** Security checks (e.g., `checkBuiltThemeConformance()` checking for stylesheet sentinels, empty `data-tovu-island` containers, and forbidden symlinks) rely on knowing exactly where entrypoints and assets live without querying framework-specific manifest variants.

---

### Question 3: Should `sourceDir` be constrained to conventions or fully exempt?
**Position: Fully Exempt Internally, with Strict Boundary Constraints.**

* **Reasoning:**
  1. **Boundary Invariants (Strictly Enforced):**
     - **Containment:** `sourceDir` must resolve strictly within the theme root folder (no `../` traversal, no symlinks pointing outside).
     - **Namespace Collision Ban:** `sourceDir` cannot match or collide with invariant root paths (`render/`, `css/`, `scripts/`, `assets/`, `ai/`, `preview/`, `theme.json`, `AGENTS.md`, `README.md`).
  2. **Internal Structure Exemption (Fully Free):**
     - Inside `sourceDir`, authors and framework tooling may use arbitrary layouts (e.g., `src/`, `components/`, `app/`, `package.json`, `tsconfig.json`, `astro.config.mjs`, `node_modules/`).
     - Tovu's runtime engine never parses or serves from `sourceDir`. It exists solely for author editing, source control, publisher lineage, and CI reproducibility. Imposing arbitrary structural rules inside `sourceDir` creates friction with upstream framework CLIs for zero runtime benefit.

---

### Question 4: Does `build.framework` need to widen?
**Position: Yes, Widen to an Open Extensible Literal Union.**

* **Reasoning:**
  1. `build.framework` is purely informative/descriptive metadata used for marketplace filtering, developer documentation, and agent context; the core engine never branches on it.
  2. Upstream themes in the wild use Svelte, Astro, Solid, Qwik, Lit/Web Components, or custom bundlers.
  3. **Type Definition:** In TypeScript/JSON Schema, widen it from `"react" | "vue" | "angular"` to include standard modern targets while permitting custom strings:
     ```typescript
     framework?: "react" | "vue" | "angular" | "svelte" | "astro" | "solid" | "qwik" | "web-components" | "custom" | (string & {});
     ```
  4. Widening is purely additive, non-breaking, and requires no runtime logic changes.

## 4. Note on Preserved Decisions and Security Boundaries

* **Settled Invariants Maintained:**
  - `render/` is invariant across both authored and generated runtime outputs.
  - `partials` (never `slots`) is the manifest key.
  - Root `AGENTS.md` remains the agent configuration entrypoint, separate from any runtime `ai/` assets.
  - Runtime tier remains `static`.
* **Security & Conformance Explicit Caveat:**
  - Standardizing the manifest shape and naming `data-tovu-agent` attributes does not substitute for real validation. 
  - Install-time integrity relies on the gate implemented in `build-conformance.ts` (verifying `artifactHashes`, checking for stylesheet sentinels, enforcing empty island containers, and strictly rejecting filesystem symlinks).
