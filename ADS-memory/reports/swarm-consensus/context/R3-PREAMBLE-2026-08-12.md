## Verified corrections since Round 2 — these override anything in the appendix

- **`EgressPolicy` has no host pinning.** The real contract is `allowedSchemes`, `denyPrivateAddresses`, `devHostAllowlist` (an *exemption* list for private-address checks, NOT a host restriction list), `maxRedirects`, `connectTimeoutMs`, `maxResponseBytes`, `maxDecompressedBytes`, `rateLimit?`. And the client method is **`HttpClientPort.send(request)`**, not `.request(...)`. Any Round 2 code assuming `allowedHosts` or `followRedirects` does not compile and does not deliver the safety property it claims. Host pinning must be asserted inside the adapter.
- **SQLite JSONB must not be persisted.** sqlite.org/json1.html: *"JSONB is a binary representation of JSON used by SQLite and is intended for internal use by SQLite only. Applications should not use JSONB outside of SQLite nor try to reverse-engineer the JSONB format,"* and the on-disk format has reserved space for future change. `better-sqlite3` bundles its own SQLite (3.49.2 here; this host's system CLI is 3.44.3, which has no JSONB at all), so an `npm update` swaps the engine under stored rows. **Round 2 participants argued the storage-spelling question without this fact — re-reason from it.**
- **Declaring a SQLite column as `JSONB` is a verified trap:** it matches none of SQLite's affinity keywords, resolves to NUMERIC affinity, and silently coerced the string `'123'` to INTEGER `123` in a direct probe. Use `BLOB` if binary is ever wanted at all.
