## Position

Deployment for Tovu must mean **Site Presentation Artifact Publishing combined with Content/Configuration Revision Promotion**. Because Tovu is a self-hostable CMS control plane ([files/tovu/cli/program.ts:30-32](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/cli/program.ts#L30-L32)), "deployment" is not re-deploying the Tovu Node.js process itself; it is exporting/building the rendered site (or triggering external host builds) and promoting reviewed content revisions between environments using Tovu’s existing `change-sets` primitive ([files/tovu/integrations-ports.ts:20](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L20)).

The owner’s working hypothesis—*"I'm thinking just MCP — so just access tokens and base URLs"*—is **fundamentally wrong on transport, security, and architectural fit**:

1. **MCP in Tovu is stdio child subprocesses, not base URLs + access tokens**: [files/tovu/mcp-federation/adapter.stdio.ts:6-8](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/adapter.stdio.ts#L6-L8) and [files/tovu/mcp-federation/ports.ts:139-149](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/ports.ts#L139-L149) confirm that Tovu's outbound MCP implementation relies on `spawnMcpStdioChannel` (`child_process.spawn`). Hosted HTTP transport for MCP is explicitly deferred ([files/tovu/mcp-federation/ports.ts:139-140](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/ports.ts#L139-L140)). Choosing MCP does not eliminate subprocesses.
2. **"Just access tokens" violates Tovu's secret architecture**: Plaintext credentials must never be stored directly or bypass encryption (Constraint C3). Tovu already provides a robust cryptographic foundation via `KeyringPort` HKDF derivation ([files/tovu/integrations-ports.ts:59-87](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L59-L87)), `SecretSealerPort` AEAD encryption ([files/tovu/integrations-ports.ts:94-97](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L94-L97)), and `IntegrationSecretRepoPort` ([files/tovu/integrations-ports.ts:158-164](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L158-L164)).
3. **MCP is the wrong transport for deterministic infrastructure jobs**: External MCP tools operate under heavy trust restrictions ([files/tovu/mcp-federation/trust.ts:57-96](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/trust.ts#L57-L96)): operator allowlists (R2), self-declared hint demotions (R3), frozen tool sets (R5), and untrusted boundary wrapping (R7). Wrapping deterministic deployment triggers in LLM tool calls adds latency, unpredictability, and prompt-injection risks ([files/tovu/mcp-federation/trust.ts:44-53](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/trust.ts#L44-L53)).

**The Right Integration Surface**: **Direct Provider HTTP Adapters combined with Event-Driven Webhook Triggers**, operating over Tovu’s guarded `HttpClientPort` ([files/tovu/integrations-ports.ts:40](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L40)) with its SSRF/DNS-pinned `EgressPolicy` ([files/tovu/integrations-ports.ts:8-9](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L8-L9)). Long-running jobs should leverage an asynchronous worker pattern mirroring `WebhookDeliveryRepoPort` ([files/tovu/integrations-ports.ts:116-155](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L116-L155)).

## Failure Modes And Sacrifice

1. **Failure Mode — Multi-Tenant Credential Bleed**:
   - Spawning CLIs or using process-level environment variables risks sharing provider credentials across workspaces. All deployment credentials must be isolated per workspace via `IntegrationSecretRepoPort` ([files/tovu/integrations-ports.ts:158-164](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L158-L164)) and decrypted in-memory strictly for the duration of the HTTP request ([files/tovu/integrations-ports.ts:96](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L96)).
2. **Failure Mode — Express Event-Loop Blocking on Long Builds**:
   - Deploys take minutes. Running synchronous deployment tasks in HTTP route handlers will cause gateway timeouts and block the server. Deploys must run asynchronously using an outbox queue pattern with claim/retry semantics ([files/tovu/integrations-ports.ts:122-148](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L122-L148)).
3. **Failure Mode — Confused-Deputy Permission Drift**:
   - Exposing deployment triggers to the embedded assistant without gating them on `admin.integrations.manage` ([files/tovu/mcp-federation/trust.ts:131](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/trust.ts#L131), [files/tovu/external-mcp/guard.ts:23](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/external-mcp/guard.ts#L23)) allows non-admin users to trigger production deployments via prompt injection.
4. **Genuine Sacrifice**:
   - Rejecting host CLI subprocesses (Option C) and generic MCP servers (Option A) means Tovu cannot claim "zero-code instant compatibility with any local CLI tool". Tovu must explicitly maintain platform HTTP adapters or structured Git webhook dispatchers.
