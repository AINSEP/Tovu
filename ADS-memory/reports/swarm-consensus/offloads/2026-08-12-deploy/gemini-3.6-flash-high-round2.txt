## Solution Slate

### Slate Ranking Criteria
1. **Security & Egress Isolation**: Strict adherence to SSRF prevention via `HttpClientPort`/`EgressPolicy` and non-leaking multi-tenant secret isolation (`SecretSealerPort`/`IntegrationSecretRepoPort`).
2. **Architectural Honesty & Transparency**: Honoring constraints C1–C6 by reflecting Tovu's true boundaries (no fake local builds, durable workspace-scoped run tracking, zero host-binary prerequisites).
3. **Operational Reliability & Resilience**: Asynchronous outbox handling, durable execution status across process restarts, and unguessable token-based callbacks.

---

### Option 1 (Leading / Recommended): Direct Provider HTTP Adapters with Outbox-Driven Run Engine
- **Architecture**: A provider-neutral `DeploymentRuntimePort` backed by HTTP adapters (e.g. GitHub REST/GraphQL) using Tovu's guarded `HttpClientPort` with `EgressPolicy`. Credentials stored encrypted in `IntegrationSecretRepoPort`. Execution runs tracked durably in workspace-scoped `deployment_runs` tables. External callbacks update runs via opaque tokens without receiving or inferring `workspaceId`.
- **Trade-offs**: High multi-tenant security, zero process-spawning overhead, strict SSRF/DNS pinning. Requires writing and maintaining dedicated provider HTTP adapters in Tovu core.
- **Genuine Sacrifice**: Sacrifice instant, zero-code compatibility with arbitrary third-party binaries or generic MCP servers; each supported provider requires a maintained HTTP adapter.
- **Cheapest Falsifying Test**: Dispatch a deployment request targeting `http://169.254.169.254/latest/meta-data/` through the adapter and verify `EgressPolicy` on `HttpClientPort` throws an egress violation before any network bytes leave the process.

---

### Option 2: Direct Git REST Tree Construction (Git-Push-as-Deploy)
- **Architecture**: Construct Git blobs, trees, and commits directly via HTTP REST APIs over `HttpClientPort` to push site source/manifests to an operator's remote repository, delegating actual builds to GitHub Actions or external CI.
- **Trade-offs**: Offloads heavy build execution to existing CI/CD pipelines while preserving `EgressPolicy` guardrails. However, payload generation requires dozens of sequential REST calls (blobs/trees/commits), introducing rate-limiting and latency risks.
- **Genuine Sacrifice**: Complete loss of direct asset deployment capability for providers that do not consume Git repositories (e.g. direct S3 or Cloudflare Pages asset uploads).
- **Cheapest Falsifying Test**: Attempt a 1,000-file static release dispatch via Git REST tree calls; measure API rate-limit failure rates against single-archive HTTP dispatch.

---

### Option 3: External MCP Server Subprocess Delegation (Owner's Proposal)
- **Architecture**: Spawn external vendor MCP servers as stdio child processes (`McpStdioLaunchSpec`) and invoke deployment tools via JSON-RPC.
- **Trade-offs**: Allows using off-the-shelf vendor MCP servers. However, `spawnMcpStdioChannel` ([files/tovu/mcp-federation/adapter.stdio.ts:308-312](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/adapter.stdio.ts#L308-L312)) executes `child_process.spawn`, bypassing `HttpClientPort`/`EgressPolicy` ([files/tovu/integrations-ports.ts:28,40](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L28)), exposing the host network, requiring daemon restarts for config changes ([files/tovu/external-mcp/put.ts:57](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/external-mcp/put.ts#L57)), and risking prompt injection ([files/tovu/mcp-federation/trust.ts:44-52](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/trust.ts#L44-L52)).
- **Genuine Sacrifice**: Complete forfeiture of SSRF protection, network egress enforcement, and multi-tenant security.
- **Cheapest Falsifying Test**: Grep `files/tovu/mcp-federation/` for `HttpClientPort` or `EgressPolicy` (0 occurrences found) and observe that an MCP stdio process can freely query internal cloud metadata endpoints.

/**
 * Concrete GitHub deployment adapter written against guarded HttpClientPort.
 * Uses GitHub App Installation Access Tokens or Personal Access Tokens over HTTPS.
 * Enforces SSRF and DNS-pinning protections via EgressPolicy (integrations-ports.ts:28,40).
 */
export class GitHubDeploymentAdapter implements DeploymentRuntimePort {
  readonly provider: DeploymentProviderType = "github";

  constructor(
    private readonly httpClient: HttpClientPort,
    private readonly egressPolicy: EgressPolicy,
  ) {}

  async triggerDeployment(input: DeploymentTriggerInput): Promise<DeploymentTriggerOutput> {
    const config: GitHubTargetConfig = JSON.parse(input.target.configJson);

    // 1. Create GitHub Deployment via REST API over HttpClientPort
    const createDeployReq: HttpRequest = {
      url: `https://api.github.com/repos/${encodeURIComponent(config.owner)}/${encodeURIComponent(config.repo)}/deployments`,
      method: "POST",
      headers: {
        Accept: "application/vnd.github.v3+json",
        Authorization: `Bearer ${input.decryptedSecret}`,
        "User-Agent": "Tovu-CMS-Deployer",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        ref: config.ref ?? input.release.gitCommitSha ?? "main",
        environment: config.environment,
        description: `Tovu release orchestration: ${input.release.name}`,
        payload: {
          tovu_release_id: input.release.id,
          tovu_run_id: input.runId,
          artifact_url: input.release.artifactUrl,
          manifest_hash: input.release.manifestHash,
          callback_url: input.callbackUrl,
        },
        auto_merge: false,
        required_contexts: [],
      }),
    };

    const createDeployRes: HttpResponse = await this.httpClient.request(createDeployReq, this.egressPolicy);

    if (createDeployRes.status < 200 || createDeployRes.status >= 300) {
      throw new Error(`GitHub deployment trigger failed (HTTP ${createDeployRes.status}): ${createDeployRes.body}`);
    }

    const deployResponseBody = JSON.parse(createDeployRes.body);
    const githubDeploymentId = String(deployResponseBody.id);

    // 2. Mark initial status as in_progress
    const statusReq: HttpRequest = {
      url: `https://api.github.com/repos/${encodeURIComponent(config.owner)}/${encodeURIComponent(config.repo)}/deployments/${githubDeploymentId}/statuses`,
      method: "POST",
      headers: {
        Accept: "application/vnd.github.v3+json",
        Authorization: `Bearer ${input.decryptedSecret}`,
        "User-Agent": "Tovu-CMS-Deployer",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        state: "in_progress",
        description: "Deployment orchestrated by Tovu CMS outbox engine",
        environment_url: input.release.artifactUrl,
        log_url: input.callbackUrl,
      }),
    };

    await this.httpClient.request(statusReq, this.egressPolicy);

    return {
      externalRunId: githubDeploymentId,
      status: "in_progress",
      detail: `GitHub deployment created with ID ${githubDeploymentId}`,
    };
  }

  async pollDeploymentStatus(input: {
    readonly workspaceId: UUID;
    readonly externalRunId: string;
    readonly decryptedSecret: string;
    readonly targetConfigJson: string;
  }): Promise<{ status: DeploymentRunStatus; detail?: string }> {
    const config: GitHubTargetConfig = JSON.parse(input.targetConfigJson);

    const req: HttpRequest = {
      url: `https://api.github.com/repos/${encodeURIComponent(config.owner)}/${encodeURIComponent(config.repo)}/deployments/${encodeURIComponent(input.externalRunId)}/statuses`,
      method: "GET",
      headers: {
        Accept: "application/vnd.github.v3+json",
        Authorization: `Bearer ${input.decryptedSecret}`,
        "User-Agent": "Tovu-CMS-Deployer",
      },
    };

    const res = await this.httpClient.request(req, this.egressPolicy);
    if (res.status !== 200) {
      return { status: "in_progress", detail: `Polling HTTP ${res.status}` };
    }

    const statuses = JSON.parse(res.body) as Array<{ state: string; description?: string }>;
    if (statuses.length === 0) return { status: "in_progress" };

    const latestState = statuses[0].state;
    switch (latestState) {
      case "success":
        return { status: "successful", detail: statuses[0].description };
      case "failure":
      case "error":
        return { status: "failed", detail: statuses[0].description };
      case "in_progress":
      case "queued":
      default:
        return { status: "in_progress", detail: statuses[0].description };
    }
  }
}

/**
 * Orchestrates a deployment run, decrypting credentials strictly in-memory
 * and dispatching via the provider-neutral port.
 */
export async function executeDeploymentDispatch(
  deps: DeploymentEngineDeps,
  input: {
    workspaceId: UUID;
    release: Release;
    environment: Environment;
    target: DeploymentTarget;
  },
): Promise<DeploymentRun> {
  const nowIso = new Date().toISOString();
  const runId = randomUUID();
  const callbackToken = `cb_${randomUUID().replace(/-/g, "")}`;

  const runRecord: DeploymentRun = {
    id: runId,
    workspaceId: input.workspaceId,
    version: 1,
    releaseId: input.release.id,
    targetId: input.target.id,
    environmentId: input.environment.id,
    status: "queued",
    externalRunId: null,
    callbackToken,
    errorMessage: null,
    logsJson: JSON.stringify([{ timestamp: nowIso, message: "Deployment run enqueued" }]),
    startedAtIso: null,
    completedAtIso: null,
    createdAtIso: nowIso,
    updatedAtIso: nowIso,
  };

  await deps.runRepo.insert(runRecord);

  // 1. Retrieve sealed integration secret
  const secretRecord = await deps.secretRepo.findById({
    workspaceId: input.workspaceId,
    id: input.target.secretId,
  });
  if (!secretRecord) {
    const errorRun: DeploymentRun = {
      ...runRecord,
      status: "failed",
      errorMessage: `Target secret '${input.target.secretId}' was not found`,
      completedAtIso: new Date().toISOString(),
      updatedAtIso: new Date().toISOString(),
    };
    await deps.runRepo.save(errorRun);
    return errorRun;
  }

  // 2. Decrypt secret strictly in-memory using SecretSealerPort (integrations-ports.ts:94-97)
  let decryptedSecret: string;
  try {
    decryptedSecret = await deps.secretSealer.open({ sealed: secretRecord.sealed });
  } catch (err) {
    const errorRun: DeploymentRun = {
      ...runRecord,
      status: "failed",
      errorMessage: `Failed to unseal credential: ${(err as Error).message}`,
      completedAtIso: new Date().toISOString(),
      updatedAtIso: new Date().toISOString(),
    };
    await deps.runRepo.save(errorRun);
    return errorRun;
  }

  // 3. Dispatch via provider adapter
  const adapter = deps.runtimeAdapters.get(input.target.provider);
  if (!adapter) {
    const errorRun: DeploymentRun = {
      ...runRecord,
      status: "failed",
      errorMessage: `No adapter registered for provider '${input.target.provider}'`,
      completedAtIso: new Date().toISOString(),
      updatedAtIso: new Date().toISOString(),
    };
    await deps.runRepo.save(errorRun);
    return errorRun;
  }

  const callbackUrl = `${deps.baseUrl}/api/webhooks/deployments/callback/${callbackToken}`;

  try {
    const output = await adapter.triggerDeployment({
      workspaceId: input.workspaceId,
      runId,
      release: input.release,
      environment: input.environment,
      target: input.target,
      decryptedSecret,
      callbackUrl,
    });

    const activeRun: DeploymentRun = {
      ...runRecord,
      status: output.status,
      externalRunId: output.externalRunId,
      startedAtIso: new Date().toISOString(),
      updatedAtIso: new Date().toISOString(),
      logsJson: JSON.stringify([
        ...JSON.parse(runRecord.logsJson),
        { timestamp: new Date().toISOString(), message: output.detail ?? "Triggered external deployment" },
      ]),
    };

    await deps.runRepo.save(activeRun);
    return activeRun;
  } catch (err) {
    const failedRun: DeploymentRun = {
      ...runRecord,
      status: "failed",
      errorMessage: (err as Error).message,
      completedAtIso: new Date().toISOString(),
      updatedAtIso: new Date().toISOString(),
    };
    await deps.runRepo.save(failedRun);
    return failedRun;
  }
}

/**
 * Express callback endpoint for external deployment provider status updates.
 * CRITICAL SECURITY INVARIANT: Does NOT accept workspaceId from caller request body/header.
 * Resolves run solely via unguessable callbackToken, then uses run.workspaceId from database.
 */
export function registerDeploymentCallbackRoute(app: Express, deps: { runRepo: DeploymentRunRepoPort }): void {
  app.post("/api/webhooks/deployments/callback/:callbackToken", async (req: Request, res: Response) => {
    const token = req.params.callbackToken;
    if (!token || typeof token !== "string") {
      res.status(400).json({ error: "missing callback token" });
      return;
    }

    // 1. Resolve run BY TOKEN ONLY — never trust caller-supplied workspace
    const run = await deps.runRepo.findByCallbackToken(token);
    if (!run) {
      res.status(404).json({ error: "invalid or expired callback token" });
      return;
    }

    const body = (req.body ?? {}) as { status?: DeploymentRunStatus; message?: string; errorMessage?: string };
    const newStatus: DeploymentRunStatus = body.status ?? "in_progress";
    const nowIso = new Date().toISOString();

    const currentLogs = JSON.parse(run.logsJson) as Array<{ timestamp: string; message: string }>;
    if (body.message) {
      currentLogs.push({ timestamp: nowIso, message: body.message });
    }

    const updatedRun: DeploymentRun = {
      ...run,
      version: run.version + 1,
      // workspaceId is taken strictly from verified DB record `run.workspaceId`
      workspaceId: run.workspaceId,
      status: newStatus,
      errorMessage: body.errorMessage ?? run.errorMessage,
      logsJson: JSON.stringify(currentLogs),
      completedAtIso: newStatus === "successful" || newStatus === "failed" ? nowIso : run.completedAtIso,
      updatedAtIso: nowIso,
    };

    await deps.runRepo.save(updatedRun);
    res.json({ ok: true, runId: run.id, status: updatedRun.status });
  });
}

/**
 * Shared workspace + authorization gate for deployment administration routes.
 * Reuses admin.integrations.manage permission (external-mcp/guard.ts:23,32-58).
 */
export async function guardDeploymentRequest(deps: DeploymentRouteDeps, reqWorkspaceId: unknown, res: Response): Promise<boolean> {
  if (String(reqWorkspaceId ?? "") !== deps.workspaceId) {
    res.status(404).json({ error: "workspace was not found" });
    return false;
  }
  const principalId = (res.locals.principalId as string) ?? "dev-user";
  const authResult = await deps.authorize({
    principalId,
    permission: "admin.integrations.manage",
    workspaceId: deps.workspaceId,
    entityType: "deployment",
  });
  if (!authResult.allowed) {
    res.status(403).json({ error: `Not authorized for deployment admin: ${authResult.reason}` });
    return false;
  }
  return true;
}

export function registerAdminDeploymentRoutes(app: Express, deps: DeploymentRouteDeps): void {
  // GET Targets
  app.get("/api/admin/v1/workspaces/:workspaceId/deployments/targets", async (req, res) => {
    if (!(await guardDeploymentRequest(deps, req.params.workspaceId, res))) return;
    const targets = await deps.targetRepo.listByWorkspace({ workspaceId: deps.workspaceId });
    res.json({ targets });
  });

  // GET Runs
  app.get("/api/admin/v1/workspaces/:workspaceId/deployments/runs", async (req, res) => {
    if (!(await guardDeploymentRequest(deps, req.params.workspaceId, res))) return;
    const runs = await deps.runRepo.listByWorkspace({ workspaceId: deps.workspaceId });
    res.json({ runs });
  });

  // POST Dispatch Run
  app.post("/api/admin/v1/workspaces/:workspaceId/deployments/runs", async (req, res) => {
    if (!(await guardDeploymentRequest(deps, req.params.workspaceId, res))) return;
    const body = req.body as { release: Release; environment: Environment; target: DeploymentTarget };
    const run = await executeDeploymentDispatch(deps.engineDeps, {
      workspaceId: deps.workspaceId,
      release: body.release,
      environment: body.environment,
      target: body.target,
    });
    res.json({ run });
  });
}

## Strongest Counter-Argument

The strongest counter-argument against Option 1 is **the ongoing provider maintenance burden**.

### Detailed Counter-Argument
By rejecting external CLI binaries (`gh`, `vercel`, `wrangler`) and third-party MCP servers, Tovu accepts sole responsibility for authoring and maintaining direct REST/GraphQL HTTP adapters for every supported deployment target. 

External hosting vendors frequently iterate on their deployment APIs, authentication requirements, and webhook contracts. Offloading execution to vendor-maintained CLI binaries or external MCP servers delegates that API churn to the vendors themselves. By insisting on first-party HTTP adapters over `HttpClientPort`, Tovu maintainers must continually update adapter code, write unit test doubles, and monitor provider schema changes.

### Why Option 1 Still Overcomes This Counter-Argument
The maintenance cost of HTTP adapters is a deliberate, necessary price paid to uphold Tovu's core multi-tenant security, host self-hostability, and network egress guarantees:

1. **Host Isolation & Portability (Constraint C1)**: Mandating vendor CLIs requires installing a fleet of third-party binaries on the host OS `PATH`, destroying Tovu's minimal single-process container self-hostability.
2. **Multi-Tenant Security (Constraint C2)**: Host CLIs write state to ambient OS configuration paths (e.g. `~/.config/gh/hosts.yml`), creating severe cross-tenant credential bleeding risks.
3. **SSRF Protection**: Subprocesses spawned via stdio ([files/tovu/mcp-federation/adapter.stdio.ts:308-312](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/adapter.stdio.ts#L308-L312)) manage their own sockets and bypass Tovu's `HttpClientPort`/`EgressPolicy` ([files/tovu/integrations-ports.ts:28,40](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/integrations-ports.ts#L28)). First-party HTTP adapters are the only approach that keeps outbound traffic strictly inside Tovu's SSRF and DNS-pinning boundary.

## What Would Change My Mind

I would revisit or alter this architectural position if any of the following technical conditions were established in the Tovu codebase:

1. **Egress-Proxied Hosted HTTP MCP Transport**: If the MCP specification and Tovu's `mcp-federation` implementation add hosted HTTP transport ([files/tovu/mcp-federation/ports.ts:139-140](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/mcp-federation/ports.ts#L139-L140)) and force all outbound RPC requests through Tovu's `HttpClientPort` and `EgressPolicy`, eliminating the stdio subprocess security bypass.
2. **Per-Tenant Execution Sandboxes**: If Tovu introduces lightweight, containerized execution sandboxes per workspace tenant, guaranteeing that third-party CLI binaries or stdio subprocesses run in isolated micro-environments without host process authority or cross-workspace credential leakage ([files/tovu/external-mcp/guard.ts:10-15](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/external-mcp/guard.ts#L10-L15)).
3. **Native Tovu Site Build Engine**: If `tovu/cli` ([files/tovu/cli/program.ts:35-60](file:///tmp/ads-peer-dispatch/debate-deploy/files/tovu/cli/program.ts#L35-L60)) gains a deterministic build/export command, transforming Tovu into an artifact producer capable of local site compilation rather than an external artifact deployment orchestrator.
