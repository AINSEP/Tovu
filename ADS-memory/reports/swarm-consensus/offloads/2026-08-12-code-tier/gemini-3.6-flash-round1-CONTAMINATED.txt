## Q2 — Tool catalog and discovery

Critique of candidate approaches:

- **Option (a) — Direct projection to MCP `tools/list` (`measured`):**
  - *At 10 tools:* Acceptable prompt overhead.
  - *At 100–1000 tools:* Fails completely. Injecting hundreds of tool definitions into system prompts consumes tens of thousands of tokens per turn. Dynamic updates to `tools/list` on tab navigation invalidate prompt KV caches, incurring high latency and token costs.

- **Option (b) — Persisted catalog (SQLite) + `search_capabilities` (`measured`):**
  - SQLite capability tables were deleted in commit `c888dc35f` because database persistence cannot represent dynamic *runtime availability*. Storage queries cannot indicate whether an active browser session currently claims a capability for a given `runId`.

- **Option (c) — Progressive exposure via Meta-Tools (`inferred`):**
  - Maintaining a static envelope of MCP tools (`execute_delegated_tool`, `discover_capabilities`) keeps prompt context at $O(1)$ static size across 10, 100, or 1000 tools.
  - `discover_capabilities` queries `ToolRegistry.list()` ([tool-registry.ts:89](file:///Users/la/.claude/harness-tmp/claude-501/-Users-la-Programming-Jini/a335a682-f3e6-4504-8913-ad6acdb321f7/scratchpad/peer-dispatch/repo/packages/core/src/tool-registry.ts#L89)) intersected with `FrontendSessionRegistry.capabilitiesFor(runId)` ([frontend-session-registry.ts:248-253](file:///Users/la/.claude/harness-tmp/claude-501/-Users-la-Programming-Jini/a335a682-f3e6-4504-8913-ad6acdb321f7/scratchpad/peer-dispatch/repo/packages/daemon/src/frontend-session-registry.ts#L248-L253)). Because discovery results are returned as tool outputs, capability state changes do not invalidate the prompt KV cache.

- **Option (d) — System prompt vocabulary descriptions (`measured`):**
  - Unmaintainable beyond a small set of fixed verbs. Expands prompt size unnecessarily and fails to reflect dynamic surface availability.

## Q4 — "Working now" vs "scales later"

### One-Way Decisions (High Reversal Cost)

1. **Tool Identity & Namespacing Scheme:**
   Tool IDs (e.g., `page.click`, `chat.send_message`) become public contracts embedded in prompt templates, audit logs, policy rules, and metrics. Changing namespacing later requires widespread migration across consumer repositories.

2. **Call-Time Authorization Enforcement:**
   Authorization must remain strictly gated at call time within `ToolExecutor` and `resolveTarget` ([frontend-session-registry.ts:163-176](file:///Users/la/.claude/harness-tmp/claude-501/-Users-la-Programming-Jini/a335a682-f3e6-4504-8913-ad6acdb321f7/scratchpad/peer-dispatch/repo/packages/daemon/src/frontend-session-registry.ts#L163-L176)). Treating discovery or list-time filtering as authorization introduces TOCTOU vulnerabilities.

3. **Engine Product Neutrality:**
   Enforcing that `@jini/protocol` and `@jini/daemon` remain free of product-specific imports is CI-guaranteed (`pnpm guard`). Introducing product DTOs into core engine packages creates tight coupling that is difficult to refactor.

### Two-Way Decisions (Low Reversal Cost)

1. **In-Memory vs Persisted Catalog Store:**
   An in-memory lookup over `ToolRegistry` and `FrontendSessionRegistry` is efficient for hundreds of tools. Migrating to SQLite FTS behind the same discovery interface later is backward-compatible.

2. **Capability Descriptor Projection Metadata:**
   Preserving original `CapabilityDef` fields (`inputSchema`, `risk`, `surface`) within `FrontendCapabilitySpec` ([frontend-capability-tools.ts:54-59](file:///Users/la/.claude/harness-tmp/claude-501/-Users-la-Programming-Jini/a335a682-f3e6-4504-8913-ad6acdb321f7/scratchpad/peer-dispatch/repo/packages/daemon/src/frontend-capability-tools.ts#L54-L59)) is an additive change with low refactoring cost.
