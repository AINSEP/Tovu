## Artifacts

Schema: `entries(type='widget')` for instances; `entries(type='widget_area')` per region (bodyJson.placements = ordered [{placementId, widgetEntryId}], fields.ext.widgets.regionKey = source of truth); `widget_region_bindings(workspace_id, region_key, area_entry_id)` UNIQUE, derived+reconciled, mirrors navLocationBindings exactly.

Resolver: `WidgetTypeRegistration` (plain data, forms/manifest.ts style) + `WidgetResolver.resolveMany(instances, ctx)` batch-first, closed `CORE_RESOLVERS` map (resolverId indexes into it, never arbitrary code), `WidgetResolveResult` = ok+ir+dependencyKeys or ok:false+reason (unknown-type/invalid-config/target-disabled/timeout/resolver-error).

Draft ADR-047 diff: replaces §2a's ordered-rows-in-binding-table language with the widget_area-entry + derived-index language; adds explicit entry_refs-not-yet-built note as a named v1 dependency; adds a new §Resolution-contract-and-failure-isolation section; changes Contact Form from "deferred" to "ships in v1 as thin Forms wrapper."

Specs: R-A (widget_area entry + reconcile invariants — one per (workspace,regionKey), seed-on-theme-activation, orphaned areas retained not deleted, whole-document OCC mutation), R-B (resolver contract — resolveMany only, per-type timeout/clamps enforced by core, D8 failure isolation, read-only resolvers), R-C (minimal entry_refs slice — table + chokepoint extractor for ref fields and widgetEmbed nodes, explicitly no polymorphic sources needed since A″ makes every source an entry).

Implementation outline: new src/widgets/ module mirroring src/navigation/ + src/forms/ layout — schema/migration, types/contracts, registry (data), ports+repo adapters, write-service+reconcile (routed through executeCommand, chokepoint-side validation), resolvers/ (one file per dynamic type — recent-entries.ts, menu.ts delegating to navigation/resolver.ts, contact-form.ts), resolver-service.ts (batch pipeline), server route wiring + render-context injection, then editor/AI surface (TipTap atom node + server-side embed-mutation command) last. Contact Form lands as one resolver file + one render component, nothing else depends on it.

Overview: reusable building blocks (contact form, recent posts, menu, text, social links) set up once and placed anywhere — theme regions or dropped into any page. Editing updates everywhere it's used; the site can say "this appears in 4 places" before you change/delete it; every rearrangement is undoable. A broken widget renders empty, the rest of the page still loads. Contact form works day one via the existing form/email system.
