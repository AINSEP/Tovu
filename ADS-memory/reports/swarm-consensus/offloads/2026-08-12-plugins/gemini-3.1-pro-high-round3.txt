## Solution Slate

**Ranking Criteria:** 
1. **Safety:** Does the solution prevent a single broken plugin from bricking the host application (`EC-10`)?
2. **Integrity:** Does the solution honor the `ADR-024` ABI freeze and structured-clone serialization rules?
3. **Ergonomics:** Does the solution maintain a clean, testable boundary between the core registry and the activation lifecycle?

**Option A (Recommended): In-Process Wiring with Circuit Breaker**
- **Approach:** Modify `loader.ts` to return the imported module. Inject an `onEnabled` callback via the composition root that calls `setup()` with a capability-scoped SDK. Implement a failure counter in `hook-registry.ts` that triggers an `onQuarantine` callback to disable the plugin after 3 consecutive failures. Deep clone the entry snapshot via `structuredClone`.
- **Trade-offs:** 
  - *Pros:* Fully resolves the `EC-10` site-bricking bug. Maintains synchronous, fast execution for valid hooks. Preserves the testable separation of concerns.
  - *Sacrifice:* Requires adding state (failure counters) into the `hook-registry.ts` singleton, slightly increasing memory overhead per attached plugin.
- **Falsification Test:** Enable a plugin that throws an error in its `beforeSave` filter. Attempt to save an entry 4 times. The first 3 should fail, but the 4th must succeed because the plugin should be automatically disabled and detached.

**Option B: Out-of-Process Quarantine (V8 Isolate Sandbox)**
- **Approach:** Move the entire plugin execution into a separate V8 isolate or Worker Thread. If the thread crashes or hangs, the main thread catches the timeout and quarantines the plugin.
- **Trade-offs:**
  - *Pros:* Provides true memory and CPU isolation. A tight infinite loop in a plugin cannot freeze the main Electron process.
  - *Sacrifice:* Monumentally expensive to engineer in the short term. Violates the immediate mandate to fix the wiring *now* using the existing architecture. Serialization overhead across threads would severely impact batch-save performance.

```typescript
import { loadPlugin, attachLoadedPlugin } from "./plugin-runtime/loader";
import { buildCapabilityScopedSdk } from "./plugin-runtime/capability-sdk";
import { setPluginEnabled } from "./plugin-runtime/activation";

// This is injected into setPluginEnabledRequired.deps in the boot/route layer
const onEnabled = async (pluginId: string) => {
  const record = currentDiscoverySnapshot.find(r => r.id === pluginId)!;
  
  const result = await loadPlugin({
    record,
    manifest: record.manifest,
    entryPath: record.entryPath
  });

  if (!result.loaded) {
    throw new Error(`Failed to load plugin: ${result.reason}`);
  }

  const sdk = buildCapabilityScopedSdk({
    pluginId,
    capabilities: record.manifest.capabilities,
    coreDeps: {
      getCurrentEntry: () => coreServices.getCurrentEntry(),
      writeExtField: (field, value) => coreServices.writeExtField(field, value),
      attachFilter: (hookName, filter) => {
        attachLoadedPlugin({
          pluginId,
          source: "site",
          hookRegistry: coreServices.hookRegistry,
          filter,
          declaredFields: record.manifest.declaredFields
        });
      }
    }
  });

  // Call setup() 
  const setupFn = result.moduleExports.default?.setup ?? result.moduleExports.setup;
  if (typeof setupFn === "function") {
    await setupFn(sdk);
  }
};
```

### 3. `plugin-runtime/hook-registry.ts` (ABI Freeze & Auto-Quarantine)
```typescript
export interface HookRegistryOptions {
  /** Called when a plugin fails repeatedly and should be disabled via setPluginEnabled */
  onQuarantine?: (pluginId: string, error: Error) => void;
}

export function createHookRegistry(options?: HookRegistryOptions): HookRegistry {
  const attachments = new Map<string, Attachment>();
  const errorCounters = new Map<string, number>();

  function attach(pluginId: string, source: AttachmentSource, filter: BeforeSaveFilter, declaredFields: readonly HookRegistryFieldDecl[]): void {
    attachments.set(pluginId, { source, filter, declaredFields });
    errorCounters.set(pluginId, 0); // Reset on clean attach
  }

  function detach(pluginId: string): void {
    attachments.delete(pluginId);
    errorCounters.delete(pluginId);
  }

  async function runBeforeSave(entry: Readonly<ContentEntryDraft>): Promise<JsonObject> {
    const ordered = [...attachments.entries()].sort(compareTb01);
    const merged: Record<string, JsonObject> = {};

    for (const [pluginId, attachment] of ordered) {
      // FIX: Deep clone nested objects to prevent live-reference mutation (ADR-024 §3)
      const snapshot: ContentEntryDraft = structuredClone({ ...entry, ext: { ...entry.ext, ...merged } });
      const ctx = { pluginId, workspaceId: entry.workspaceId };

      let patch: unknown;
      try {
        patch = await attachment.filter(snapshot, ctx);
        errorCounters.set(pluginId, 0); // Reset on success
      } catch (error) {
        const failures = (errorCounters.get(pluginId) ?? 0) + 1;
        errorCounters.set(pluginId, failures);

        const hookError = new PluginHookFailedError(pluginId, `filter failed: ${error instanceof Error ? error.message : String(error)}`, { cause: error });

        // Auto-quarantine on 3 consecutive failures
        if (failures >= 3) {
          detach(pluginId);
          options?.onQuarantine?.(pluginId, hookError);
        }
        
        throw hookError;
      }
```

## Critique Of Another Participant's Round 2 Code

I am critiquing **gemini-3.6-flash-high-round2**'s proposed ABI specification change regarding the `beforeSave` filter type signature. 

They observed that `hook-registry.ts:170` executes `patch = await attachment.filter(snapshot, ctx);` and concluded:
> *"The specification documentation must be updated to explicitly require `Promise<ExtPatch>`, enforcing ADR-024 §3's async-only rule"*

**This is incorrect and ergonomically unsafe.** In TypeScript/JavaScript, the `await` keyword safely unwraps both Promises and synchronous values. By forcing the spec to strictly require `Promise<ExtPatch>`, `gemini-3.6-flash-high` would force every single plugin author to wrap their fast, synchronous filters (e.g., a simple word counter) in `async () => ...` or `Promise.resolve(...)`. 

The correct signature mapping for a transport-agnostic ABI that gracefully handles in-process execution is `(entry, ctx) => ExtPatch | Promise<ExtPatch>`. The registry's usage of `await` perfectly supports this union without requiring the author to artificially promisify their code. Updating the spec to strictly mandate a Promise introduces friction, harms V8 optimization for synchronous paths, and breaks standard JS idioms.
