## OWNER DECISIONS (approved 2026-10-20; implement exactly)
- ONE plugin `content/agent-plugins/google-workspace`: the Google sign-in (declares its OAuth config, uses the generic Jini OAuth engine + vault) and every product as a module. v1 ships Sheets only; Docs/Slides/Drive/Gmail/Calendar later on the same sign-in. Products enabled separately; enabling a product and granting its scopes are separate steps. Disabling a product blocks its tools and its form delivery; neither silently revokes authorization.
- ALL Google-specific code (endpoints, scopes, request formats, response parsing, revocation, Picker) lives in the plugin. NOTHING Google-specific in Jini or Tovu core. Plugins never import each other.
- Sign-in: Tovu-owned Google OAuth clients (separate Desktop and Web client identities; ids are config placeholders), consent-screen name "Tovu". Known callback origins first (placeholder config list) + BYO client as an advanced option via the existing secure credential capture (never pasted into chat). Default scope `https://www.googleapis.com/auth/drive.file` only; no broad Drive or all-spreadsheets scope.
- Desktop: installed-app client, PKCE S256, ephemeral loopback listener on 127.0.0.1, consent AND Picker in the SYSTEM browser; adding a product = explicit re-consent for the full intended scope set, verify the grant, replace credentials atomically (installed apps have no incremental auth). Hosted: Web client, registered HTTPS callback, server-held secret, `include_granted_scopes=true`, offline access; keep a valid refresh token when a same-account exchange omits a new one.
- Account actions: reconnect (same account, same connectionRef), switch account (stage, verify identity, ask which bindings to reassign; frozen jobs never silently change account), disable product, revoke (stop use, call Google revocation, clear local tokens on success; on remote failure show "Disconnected locally; Google revocation pending", keep the disabled sealed credential for retry, link the Google account-access page; never claim remote revocation succeeded). `invalid_grant` → "Reconnect required", undelivered jobs kept.
- Sheets tools: broad GA coverage per PLAN-google-workspace-codex.md §D (26 tools, `p_google_workspace__<local>`), destructive ops through Tovu's confirmation rules, bounds per §D, safe error codes with `retryable`, `retryAfterMs`, `outcome: 'not-applied' | 'unknown'` and a next action. An uncertain append/create/copy is never auto-replayed. CSV export of a tab = bounded values reads + CSV encoding (no undocumented gid URLs); error instead of a partial export.
- Pick existing sheet = Google Picker (drive.file grant per picked file) + create-new. A pasted URL grants nothing. Hosted Picker: authenticated non-cacheable bootstrap gives the surface ONLY a short-lived access token + public config; server verifies session, account, MIME type and real API access before saving the selection; chat gets resource metadata only. Desktop: native Picker in the system browser (code+PKCE, loopback, `prompt=consent`, `trigger_onepick=true`, spreadsheet MIME filter; `picked_file_ids` arrives as a plugin-declared callback field and is trusted only after state/code + API verification). Cancel leaves settings unchanged.
- Links rendered as buttons are fine for connect/reconnect/open-in-browser actions.
- Quotas: plugin-declared budgets through the real http-kit limiter, starting ~45/min per user and ~240/min per instance; honor Retry-After; jittered backoff; never drop a submission on quota.
- Form delivery: push-only destination (`tovu-form-destinations.json`, no `receive`), same Sheets client as the tools; mapping + dedupe per PLAN-google-workspace-codex.md §F (tab per form by numeric sheet id, stable field ids, labels as headers, `_tovu_submission_id` + submitted time, IP excluded, checkbox groups joined ", ", RAW values, new fields appended as columns, frozen mapping per job, actionable mapping errors; dedupe = scan the submission-id column in bounded chunks before every append and again after an uncertain append, 50,000-id ceiling → `destination-limit`, no row reservations, at-least-once with best-effort dedupe documented). Local delete leaves external rows (say so when enabling).
- Cut: service accounts, OAuth broker, whole-Drive browsing, backfill, scheduled imports, bidirectional sync, external-row purge, exactly-once delivery, per-request-kind wrappers beyond §D.
