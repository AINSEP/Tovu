# ADR-059: Assistant Transport Reopens ADR-049 — AG-UI as an Additive Canary Path

- Status: Accepted (owner sign-off in conversation, 2026-08-18) — **⚠️ Decision 3 AMENDED same-day.** The canary proved out live (10 real Tovu tool calls through a real browser, clean). Decision 3's "hand-roll everything, no `@ag-ui/*` packages" reasoning conflated two separate projects: `@ag-ui/core`/`@ag-ui/client`/`@ag-ui/encoder` are MIT-licensed, free, own-nothing-to-CopilotKit packages published by the neutral `ag-ui-protocol` org (confirmed directly against their GitHub repo) — completely distinct from CopilotKit's own commercial React layer, which is what the "avoid CopilotKit-adjacent deps" reasoning was actually worried about. See the amended Decision 3 and Consequences below.
- Date: 2026-08-18
- Author: Claude Opus 5 / Leona Burime
- Supersedes: ADR-049's transport conclusion only (Decision 1: "wire protocol is `@jini-ai/protocol` + `@jini-ai/daemon`'s canonical run-event stream, not AG-UI"). ADR-049 Decisions 2–7 (tool execution via `@jini-ai/core`/`@jini-ai/daemon`, the Profile model, `features/*/agent-tools.ts` catalogs, multi-agent support, in-page DOM control, the reuse boundary) are unaffected and remain in force.
- Relates: ADR-049 (the decision being reopened), ADR-013/014 (AG-UI's original 2026-07-05 choice, which this ADR partially restores), `development/todos.md`'s 2026-08-17 "Retrofit the assistant transport onto AG-UI + CopilotKit" entry (the owner's own override note, superseded in form — not substance — by this ADR), and the illustrative prototype at `ADS-memory/reports/architecture/2026-08-18-ag-ui-sample/`.

## Context

ADR-049 (Accepted, 2026-07-28) rejected CopilotKit + AG-UI as Tovu's assistant transport, reasoning that adopting `@jini-ai/chat-react` + `@jini-ai/daemon`'s own hand-rolled event vocabulary was less duplicate work than re-deriving an equivalent permissioned tool-registry/run-lifecycle stack on top of AG-UI. That reasoning was about *tool execution and the run lifecycle*, not about the *wire format* in isolation — ADR-049 itself never argued AG-UI the protocol was bad, only that building Tovu's whole assistant stack around CopilotKit's client and AG-UI's protocol was premature relative to a real, versioned, already-integrated kit (`@jini-ai`) doing the harder parts.

On 2026-08-17 the owner recorded an explicit override in `development/todos.md`: AG-UI is a stable, public protocol worth having *in addition to* the existing transport, even at the cost of some duplicate plumbing — framed as a **port-and-adapter retrofit**, not a rip-and-replace. That entry itself flagged that reversing an Accepted ADR needs its own superseding ADR before real implementation, not just a todo checkbox — this document is that ADR.

Two independent research passes converged on materially the same technical shape before this ADR was written:

1. A same-day illustrative prototype (`2026-08-18-ag-ui-sample/spec.md` + two `.sample.ts/tsx` files, explicitly marked "not wired in") — produced by a separate session, working from the todo entry.
2. A Milestone-1 design pass by a dispatched Programmer subagent, working from this repo's real source (`assistant-transport.ts`, `assistant.ts`, `protocol-surfaces.spec.md`, `@jini-ai/chat/core`'s port, and `@ag-ui/core`'s real current schema pulled via context7), done without reading the sample first.

Both agree: the integration seam is `chat-core`'s already-reduced `AgentEvent` vocabulary (the one place Tovu's two existing backend paths — Local CLI and BYOK — already converge), not either path's raw wire format; the shape is a third, flagged, deletable `ChatTransport` implementation; nothing about the existing Local CLI or BYOK paths changes; and `mcp-ui`/`a2ui` (Jini's own, unrelated generative-UI channels, despite the similar name to AG-UI) stay unsolved and out of scope for this slice.

They diverge on dependencies and rendering, and this ADR resolves that divergence for the current slice (see Decision 3).

**A real licensing finding surfaced during research, not by design intent:** the todo's step 4 (eventually drop `AssistantDock`'s own rendering for CopilotKit's `useCopilotChatHeadless_c` headless hook) targets a **paid Early Access Premium** feature gated behind a Copilot Cloud license key. This is a real tension with the "AG-UI is a stable *public* protocol" rationale — the *protocol* is open; that *specific convenience hook* is not. This ADR does not decide that question; it explicitly defers it (see Decision 4).

## Decision

1. **AG-UI becomes a second, additive `ChatTransport` implementation — canary, not cutover.** Reopens ADR-049's transport conclusion to that extent only. The existing Local CLI and BYOK paths (`apps/admin/src/lib/assistant-transport.ts`, `src/server/modules/assistant.ts`, `src/assistant/agent-daemon-server.ts`) are unmodified. Selection is a Tovu-local, independently-flagged toggle — not an extension of Jini's own closed `ExecutionConfig.mode` union (`@jini-ai/ui`, a separate repo/package) — so this stays a zero-touch addition to Jini and a reversible one in Tovu: deleting the new files and the toggle fully reverts to ADR-049's current state.

2. **The adapter translates `chat-core`'s `AgentEvent` (not either backend's raw wire format) into real AG-UI wire events, server-side.** One translation function covers both existing backend paths for free, matching the reduction `translateRunAgentPayload` already performs today. The new server route wraps the *same* daemon-backed run lifecycle `assistant.ts`/`assistant-byok.ts` already use — per `src/server/__specs__/90-migration/protocol-surfaces.spec.md`'s standing rule, a protocol adapter is still a server surface: it must resolve to existing server commands, not a new execution path, and permission checks (`requireAdminSession`) happen before command execution, not inside the adapter as an afterthought.

3. ~~This slice stays fully hand-rolled: no `@ag-ui/core`, `@ag-ui/client`, `@ag-ui/encoder`~~ **AMENDED, same day, after the canary proved out live.** Adopt the real `@ag-ui/core` (types/schema) and `@ag-ui/client` (the `HttpAgent` class — handles the actual HTTP/SSE run lifecycle) on the client side, and `@ag-ui/core` + `@ag-ui/encoder` (SSE/protobuf event encoding) on the server side. Reasoning for the reversal: the original "avoid the CopilotKit-adjacent dependency graph" concern doesn't actually apply to these three packages — they are MIT-licensed, published by the neutral `ag-ui-protocol` org, require no account, no license key, and share no code or governance with CopilotKit at all. That distinct concern is real for `@copilotkit/react-core`'s hooks (`useCopilotChatHeadless_c` specifically requires signing up for a CopilotKit account and a `publicLicenseKey`, confirmed directly against CopilotKit's own docs source) — but this decision does not touch that package at all, and still doesn't. Net effect: Tovu stops hand-tracking AG-UI's own wire schema and event shapes itself (the exact risk already flagged in Milestone 2's build — a manually-synced port with "no automated drift check", and the `REASONING_MESSAGE_*` fields that had to be guessed by analogy because they weren't in the schema dump available at the time) — the real package IS the schema, kept current by upstream, not by Tovu re-deriving it by hand each time the protocol evolves.

   `AssistantDock`'s rendering stays unchanged either way — `@ag-ui/client`'s `HttpAgent` replaces the hand-rolled `fetch`/SSE-parsing loop in `assistant-transport-ag-ui.ts`, wrapped to still implement Jini's `ChatTransport` port; the event-translation functions (`AgentEvent` ↔ AG-UI event) keep their shape but now type against the real `@ag-ui/core` union instead of a hand-rolled approximation. No parallel rendering component, no CopilotKit package, no change to the Local CLI/BYOK paths — everything else about this ADR's scope and blast-radius reasoning holds.

4. **The todo's step 4 (CopilotKit headless-mode rendering swap) is explicitly deferred, not decided here.** It requires its own licensing conversation (Copilot Cloud key, Early Access Premium terms) before anyone commits engineering time to it. This ADR's scope ends at "AssistantDock can optionally speak AG-UI on the wire"; whether AssistantDock's own rendering is ever replaced by CopilotKit's is a separate, later decision.

5. **`mcp-ui`/`a2ui` remain unsolved for the AG-UI path, on purpose.** Both are Jini's own generative-UI channels, confirmed unrelated to AG-UI (ADR-049's own correction, reconfirmed 2026-08-17). The adapter passes them through as an inert `CUSTOM` event so nothing throws; no renderer exists for that payload on the AG-UI path. If those features need to work identically on both transports for the canary to be a fair comparison, that is separate, explicitly scoped follow-up work — not assumed to come free with this ADR.

6. **Message/reasoning-boundary synthesis is a named, load-bearing risk, not an implementation detail.** Tovu's `AgentEvent` stream carries no explicit start/end signal for `text`/`thinking` runs beyond a change in `kind` — the adapter must infer `TEXT_MESSAGE_START`/`END` and `REASONING_*` boundaries itself. Getting this wrong risks a real AG-UI client rejecting a double-START with no intervening END (a documented failure mode in AG-UI's own ecosystem). Implementation must include a regression test covering interruption sequences (e.g. text → tool_use → text again), not just the happy path.

## Consequences

- ~~No new dependencies land with this ADR~~ **AMENDED**: `@ag-ui/core` (root + `apps/admin`), `@ag-ui/client` (`apps/admin` only), `@ag-ui/encoder` (root only) are added. All three are MIT-licensed with no transitive dependency on any `@copilotkit/*` package — verified before adoption, not assumed. The footprint otherwise stays the same two files (one server module, one client transport module) plus the local toggle; still independently deletable, just with three real dependencies instead of zero.
- **Run-id ownership shifts client-side for this path only.** AG-UI's `RunAgentInput` expects a client-supplied `run_id`/`thread_id`; unlike the daemon-backed Local CLI path (server-minted, reattachable), the AG-UI path mints client-side (mirroring BYOK's `mintByokRunId` precedent) and carries no reattach-after-reload support in this slice — an explicit, disclosed limitation, not an oversight.
- **The fuller CopilotKit-inclusive shape sketched in the 2026-08-18 sample prototype is not built by this ADR.** That sketch remains a valid reference for a *later* slice if the hand-rolled canary proves the protocol out and the team decides the CopilotKit client/dependency cost and the licensing question in Decision 4 are worth taking on. It is not superseded, only not adopted yet.
- **Nothing about ADR-049 Decisions 2–7 changes.** Tool execution, the Profile model, multi-agent support, and the reuse boundary all still route through `@jini-ai/core`/`@jini-ai/daemon` exactly as ADR-049 decided, regardless of which transport a given turn uses.
- **Stale cross-references to fix when this lands:** `development/todos.md`'s 2026-08-17 entry should be marked resolved-by-this-ADR (its own text already asked for this); the Master Build Inventory §12 reference noting "ADR-013 names AG-UI... no implementation yet" needs updating to point here instead.
