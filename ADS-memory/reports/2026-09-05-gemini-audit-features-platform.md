**MEDIUM — CONFIRMED.** `apps/website/src/features/custom-credentials/credentialed-request.ts:305-313` (`redactResponseHeaders`), commit 922f2ef6. Response-body redaction got a documented length floor (`MIN_SAFE_BODY_REDACTION_TOKEN_LENGTH = 8`, `resolveRedactedResponseBody:337`) specifically because short tokens over-match ordinary content — but `redactResponseHeaders` applies no floor at all: it drops any header whose value `.includes()` a secret, regardless of length. Nothing in this codebase enforces a minimum `connection.token` length at credential-creation time (checked `types.ts`/`store.ts` — no such validation), so a real, if self-inflicted, credential with a 1-2 character token causes any response header that happens to contain that substring (a digit in a `Date` header, `ETag`, part of a `Content-Type`) to be silently dropped, with **no signal to the caller that anything was withheld** — unlike the body path, which substitutes a `BODY_WITHHELD_SHORT_TOKEN_MARKER` the caller can act on.
