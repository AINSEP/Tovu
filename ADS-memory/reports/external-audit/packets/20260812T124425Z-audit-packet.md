## Threat Model & Scope Contract (FROZEN — `TM-TOVU-2026-08-12-B`)

**Product context.** Tovu is a self-hosted CMS. Two distinct surfaces:
- A **public site** (server-rendered HTML) served to anonymous readers at internet scale.
- An **admin** (React SPA) used by a small number of authenticated operators, sometimes concurrently.

**Risk tier:** medium/high. **Score floor: 8.5.**

**Allowed actors and capabilities:**
1. Anonymous public visitor — issues GETs to public routes; may be a crawler, prefetcher, or CDN.
2. Authenticated admin operator — full admin capability. **Two operators may act concurrently on the same record.**
3. Content author — supplies arbitrary document content (TipTap JSON) including pasted/imported material.
4. A caching intermediary (CDN/browser) that honors `Cache-Control` literally.

**In-scope BLOCKING failure domains (ALLOWLIST — a blocking finding must map to exactly one):**
- **D1 — Unsafe or disclosing content reaches public HTML.** XSS, credential leakage, internal-routing disclosure.
- **D2 — Wrong or wrongly-cached content served.** A visitor receives content intended for someone else, a stale value past its declared window, or a state-mutating response is made cacheable.
- **D3 — Silent content loss or writing to the wrong record.** An admin save persists a value the operator did not enter, reverts a concurrent operator's committed write, or targets the wrong entity.
- **D4 — Unrecoverable break.** Process crash, unbounded hang, event-loop starvation, or an admin/site that fails to boot.
- **D5 — Regression introduced by this diff.** Previously-working behavior broken by these changes, including a test that no longer asserts what it claims.

**Mandatory invariants:**
- **I1** No author-supplied value reaches public HTML without passing the established sanitisation path.
- **I2** A response that mutates server state is never marked cacheable.
- **I3** An admin save transmits only fields the operator actually changed, diffed against a baseline the operator actually saw.
- **I4** A public page render always terminates and returns either valid HTML or a clean error — never crashing the process, never blocking the event loop unboundedly.
- **I5** Data displayed in the admin corresponds to a value the server actually returned.
- **I6** The `App.tsx` extraction is behavior-preserving: no runtime behavior differs from before the refactor.

**Escape valve:** a catastrophic issue *outside* these domains goes in `out_of_scope_fatal_warnings` — it must NOT lower the score or flip the gate.

**Gate formula (coordinator recomputes; auditor-supplied gate is not trusted):**
`blocking_gate = FAIL if (any validated blocker mapped to D1-D5 is unresolved) OR (score < 8.5)`.
Blocker classification happens BEFORE scoring; the two are independent and neither rescues the other.

## Scope — the 9 commits under review

| # | Commit | Change |

| 1 | `df109b5` | **Comments lost-update fix.** `use-comment-settings.hooks.ts` re-seeded its save-diff baseline from every successful load, including background refetches. Since the form is uncontrolled (`defaultValue`/`defaultChecked`), the baseline moved while the DOM did not, so a later save silently reverted a concurrent operator's committed write. ## Verification NOT performed

- **No real CDN or proxy** was placed in front of the new `Cache-Control` headers.
- **No multi-process / real-concurrency test** of the two-operator scenarios; both lost-update tests simulate concurrency within one process.
- The `renderViaTemplate` `/:slug` branch received a cache header on **structural grounds** (it never receives `req`); its cacheability was NOT byte-diffed across cookies the way the other two branches were.

- Mutation testing was not run on any touched file.

## Known risks and open questions

- `staleTime: 10_000` opens a window where a second operator's committed change is invisible on navigate-back. Accepted deliberately; writes still refresh via invalidation.
- Express computes a weak ETag on every response but a matching `If-None-Match` still returns 200 (reproduced on a bare Express 4.22.2 app), so conditional GET provides nothing today.
- `/store/buy` is a GET that mutates state, documented in its own file header as a spike simplification. **It is in the repo but out of this diff's scope** — noted so it is not mistaken for something this diff introduced.
- Breadth (100k sibling nodes) blocks the event loop ~250-650ms without crashing; no node-count bound was added.
