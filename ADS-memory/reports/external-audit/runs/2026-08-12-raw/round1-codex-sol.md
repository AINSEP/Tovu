What looks solid and should remain:

- Keep `render.ts` refusing arbitrary `attrs.src`. Removing that boundary would create a direct stored-content URL surface.
- Keep saved and unsaved content flowing through the same renderer, with POST preview using the existing authorization and no persistence operation.
- Keep TanStack Query behind the local adapter and its import restriction.
- Keep effect-local cancellation for loaders whose lifetime is exclusively one effect invocation.
- Keep the explicit media context threaded through both public and preview rendering.

File-level guidance:

- `src/server/http/site/render.ts`: add a hostile-input matrix for every node, mark, and emitted attribute. Verify URL schemes separately from HTML escaping.
- `src/widgets/resolver-service.ts`: prove the pending-body override occurs before all rendering and media-reference collection, never enters a write path, and cannot reuse saved-body-derived unsafe HTML.
- `src/server/routes/admin/posts/template-preview.ts`: add assertions for authorization, no database writes, malformed JSON, 413 handling, deeply nested documents, and identical saved-versus-preview output.
- `apps/admin/src/lib/media-image-extension.tsx`: remove or clearly mark URL images as unsupported until secure ingestion exists.
- `apps/admin/src/features/*/hooks/*.hooks.ts`: classify loaders by invocation source; multi-source loaders need generation-based suppression, not merely effect cleanup.
- Translation contracts: arity is descriptive, not a strong semantic boundary; use distinct wrappers or methods if preventing cross-wiring matters.
