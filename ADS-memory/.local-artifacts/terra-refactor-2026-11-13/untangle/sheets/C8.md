## 0. Decisions (reviewer: check first)
1. **Core is types + pure helpers, no zod.** `ui`'s `chartSpecSchema` (zod) stays in ui; core restates `ChartSpec` as a plain interface and ui proves equality with `chartSpecSchema satisfies z.ZodType<ChartSpec>` (ui imports core: allowed).
2. **Core has no DOM lib** (`tsconfig.base.json` lib = ES2023). Chart provider ABI is generic over the element: `ChartProvider<E = unknown>`; ui aliases `ChartProvider = CoreChartProvider<HTMLElement>`.
3. **Form collection is generic vocabulary → core** (three packages agree nominally: cms registry, admin settings UI, provider-plugins formspree/google-forms; no field-registry policy in it). This narrows DESIGN §2.5's list: forms is no longer a Q6 restated domain port. `FormSubmissionEvidence` goes to core generic over the field-type name; the **field registry, file-type allow-list, pattern check and HTML escaper stay in cms** (domain policy) and reach admin through the `formsCatalog` port.
4. **Plugin SDK → core** as the type closure providers implement against (`PluginSdk` and what it references) plus two pure values: `PluginProviderStartupError` (data-only class) and `hasProviderAuthHeader`. The manifest validator, provider host and contribution registry stay in `plugins`.
5. **Domain helpers reach providers through the domain's provider contract descriptor.** `PluginProviderContract` gains `context?: Readonly<Record<string, unknown>>`; the provider host passes it to every factory as `optional.context` (merged under host `factoryOptions`). Each domain exports its contract with its helpers (`paymentsProviderContract.context = { paymentError, moneyProblem }`, `observabilityProviderContract.context = { redactOperationAttributes, describeReportedError, describeTelemetryFailure, resolveObservabilityConfig, createAsyncLocalSpanScope }`). Providers restate the context type structurally (Q6) and never import the domain. Browser chart providers get `applyTheme` in the `mount` input from ui instead.
6. **`createOtelObservabilityPort` moves to the OTel provider.** It is OpenTelemetry semantic-convention mapping (`http.request.method`, `db.system.name`, `exception.type`, `otel.ts:80–190`) over OTel-shaped factory ports, and its only code caller besides diagnostics' own selector is `provider-plugins/src/observability-opentelemetry/opentelemetry.ts:294` (Tovu calls only `createNoopObservabilityPort`). Owner rule: vendor code in its plugin. diagnostics keeps the vendor-neutral `ObservabilityPort`, noop, fan-out, redaction helpers. diagnostics' `createObservabilityPort` selector (`index.ts:18–25`, no code callers; docs + CHANGELOG only) is **deleted** with a CHANGELOG "Breaking" entry (0.x, A4 precedent).
