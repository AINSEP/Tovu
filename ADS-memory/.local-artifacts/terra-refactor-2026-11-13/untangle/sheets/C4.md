## 0. Decisions this sheet makes (reviewer: check these first)
1. **Core never imports `@jini-ai/protocol`** (core has zero dependencies, B2/L6). So core restates the wire error shape structurally as `ServerApiError` (same precedent as `JsonValue`, which core and protocol each restate "so the foundational protocol never imports a kernel package"). `protocol`'s `ApiError` and core's `ServerApiError` are mutually assignable; a typecheck file in http-kit (which imports both) proves it.
2. **d2's universal pieces land in core, not in `http-kit/server-port`.** `matchServerPath`, `createRouteTable`, `withServerMiddleware`, `jsonResponse`, `readQuery`, `readBodyBytes`, `readJsonBody`, `DEFAULT_JSON_BODY_MAX_BYTES` are web-standard and pure (state only in the returned object), and daemon/cms route code needs them; in http-kit they would be a forbidden domain→http-kit edge. d2's `ReadJsonBody` port (core settings could not import http-kit) becomes unnecessary: core settings calls core's `readJsonBody` directly (O4 simplifies).
3. **http-kit keeps only Node/Express-facing code:** `node-bridge` (`createNodeDispatcher`, `createNodeGate`, `writeNodeResponse`, `createNodeServer`), the legacy Express `mountJsonRoute` (deprecated, deleted in O6), the Node `req` guards (`api-security-middleware`, `local-daemon-request`, `trust-proxy`, `rate-limit`), `reportRouteInternalError` (node:crypto + console default sink) and `html-response`. **Deviation from d2 §10.1** (lead/owner rule "no server framework in Jini beyond http-kit's adapter"): the Express adapter `createExpressServer`/`expressGate` lives in http-kit `./express-adapter`, typed **structurally** (Connect-style `use(handler)` over `IncomingMessage`/`ServerResponse`), so http-kit still has no `import … from 'express'` outside devDependency tests. Tovu's `express-server.ts` (d2 §5) shrinks to binding `TOVU_API_KEY_REDACTION`.
4. **Route modules return `ServerRoute[]`** (DESIGN §2.2 registration pattern): `fooRoutes(required, optional): ServerRoute[]`. `jsonRoute({ spec, deps }, { host }) → ServerRoute` replaces `mountJsonRoute({ app, spec, deps, adapter })`. Hosts do `for (const route of routes) server.route(route)`. This satisfies the owner rule "code takes `{ app: Server }`" at the host boundary, and keeps the d2 mount rule (one dispatcher per registration line) intact.
5. **`RouteHostContext` replaces `AdapterContext`** (same fields, framework-free): `OriginContext` (`resolvedPortRef`, `env: Readonly<Record<string,string|undefined>>`, env-var names) + `onInternalError?` + `reportInternalError` port. http-kit re-exports `AdapterContext = RouteHostContext` so the 25 importers compile unchanged.
6. **Owner decisions folded in:** Q4 = `DAEMON_JSON_BODY_MAX_BYTES = 6 MiB` on every host (daemon constant, O5); Q5 = **refuse non-identity `content-encoding` with 415, never unzip**: core `readBodyBytes` does it, with the owner's why-comment verbatim.
7. **`spec.method` stays lowercase** (`HttpMethod`), mapped to `ServerMethod` inside `jsonRoute`, so the ~83 daemon specs change no `method:` line.
8. **SSE:** one web-stream helper `createSseStream()` in core over a pull-based `ReadableStream` with the existing bounded queue (SEC-006, 1000), keepalive through a **required** injected scheduler (H2, §11; no default in core). It replaces both `createSseChannel` (sse.ts) and `createSseResponse` (raw-sse.ts) at O3; C4 only adds it.

```ts
/** Tovu's binding of Jini route lists onto Express. Mount rule (server-port.md §5): call this ON THE LINE
 * of each former `register*Routes({ app })`, so every gate mounted above still runs first. */
export function mountJiniRoutes(
  { app, routes }: { app: Parameters<typeof createExpressServer>[0]["app"]; routes: readonly ServerRoute[] },
  _optional: Record<string, never> = {},
): void {
  const server = createExpressServer({ app }, { redactionPatterns: [TOVU_API_KEY_REDACTION] });
  for (const route of routes) server.route(route);
}

/** Built once per daemon scope from the values `agent-daemon-scope.ts:1434` builds `adapter` from today. */
export const routeHost = (required: { port: number; env: Readonly<Record<string, string | undefined>>; onInternalError: RouteHostContext["onInternalError"] }): RouteHostContext =>
  ({ resolvedPortRef: { current: required.port }, env: required.env, allowedOriginsEnvVar: "TOVU_ALLOWED_ORIGINS", webPortEnvVar: "TOVU_WEB_PORT", bindHostEnvVar: "TOVU_BIND_HOST",
     onInternalError: required.onInternalError, reportInternalError: reportRouteInternalError }) satisfies RouteHostContext;
```
