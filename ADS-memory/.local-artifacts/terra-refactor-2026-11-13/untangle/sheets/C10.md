## Decisions (read first; two change DESIGN §2.4)
1. **Most of the 18 surface lines are wire vocabulary, not implementations, so they move down instead of being injected.**
   - `agentic/src/core/a2ui/` (9 files, 2,005 lines) is, by its own module doc, "A2UI v1.0 wire types and a minimal client interpreter". It imports only `zod` and one `Clock` type from core. It has no DOM, no Node, no module-scope state, and nothing in agentic imports its internals. That is B3 (protocol: wire schemas + pure constructors/guards; zod is protocol's only dep). It moves to **`@jini-ai/protocol/a2ui`**; `@jini-ai/agentic/a2ui` becomes a one-line re-export.
   - `ui/src/features/mcp-ui/resource.ts` (348 lines, zero imports: `parseUIResource`, `readActionPlan`, `readExpiresAt`, `readPreferredFrameSize`, `UIResource`, `McpUiActionPlan`, ...) and the two host-callback types `McpUiToolCall`/`McpUiToolCallHandler` (ui `react/mcp-ui/useMcpUiHost.ts:88-99`) are MCP-UI wire vocabulary. They move to **`@jini-ai/protocol/mcp-ui`** (the subpath C2 creates), as file `protocol/src/mcp-ui/resource.ts`.
   - `agentic/src/core/capability.ts` (types only: `CapabilityDef`, `CapabilityInputSchema`, `CapabilityInputProperty`, `CapabilityRisk`, `CapabilitySurface`) is agent-tool vocabulary shared by agentic and chat → **`@jini-ai/core/contracts/capabilities`**.
   - Result: chat `run-activity.ts` (non-React core code, which a React port could never reach), `A2uiSurfaceCard.rules.ts`, `mcp-ui-question-input.ts`, `useSurfaceRecovery.ts`, `mcp-ui-surface-state.ts`, `create-mcp-ui-tool-caller.ts`, `chat-capabilities.ts`, `agent-tools.ts`, `core/agentic/index.ts` become plain base repoints (R4).
2. **No `UiSurfacesProvider`.** ui's one `agentic/a2ui` line (`ui/src/features/a2ui/protocol.ts:6`) is a re-export of 2 factories + 9 types. ui's own code only uses the types. After decision 1 it becomes `export { ... } from '@jini-ai/protocol/a2ui'`, a base import (R5 edits it). Nothing in ui calls the factories, so a provider would inject nothing. (If the owner still wants ui's public `createA2uiInterpreter` re-export dropped, that is a one-line changeset note, not a port.)
3. **What stays a real port (React, chat):** the things that are implementations: the MCP-UI iframe host component, the interactive-ui component registry (renders React components), the registry→catalog builder (ui's), and WebMCP model-context detection (agentic/dom). That is `ChatSurfaces`, provided by `ChatSurfacesProvider` in a **separate file `chat/src/react/surfaces.tsx`**, so C10 never touches C9b's `chat/src/react/kit.tsx`. C9b's `ChatKitProvider` may nest it (`kit.surfaces` → `<ChatSurfacesProvider surfaces={kit.surfaces}>`) so hosts mount one provider; recommended.
4. **The page-capability runtime port is not React.** `embed-widget/browser/frontend-session-bridge.ts` already receives `pageDriver` through its options; it also imports `PAGE_CAPABILITIES` and `executePageCapability`. C10 declares `ChatPagePort` (types only, `chat/src/core/page-port.ts`): `{ capabilityIds: readonly string[]; execute(required: { capabilityId: string; input: Record<string, unknown> }, optional?: { signal?: AbortSignal }): Promise<unknown> }`. R4 swaps the option `pageDriver?: PageDriver` for `page?: ChatPagePort` (chat never calls driver methods; it only forwards the driver). Tovu `App.hooks.ts:1134-1169` binds `page: { capabilityIds: PAGE_CAPABILITIES.map(c => c.id), execute: (r, o) => executePageCapability({ driver: pageDriver, ...r }, o) }`.
5. **`chat/src/react/index.ts:375` re-export of `createDomPageDriver`/`currentAgentPage`/`DomPageDriverOptions` from agentic/dom is deleted** (R4). Tovu already imports `createDomPageDriver` from `@jini-ai/agentic/dom` everywhere (9 sites, rg-checked); no Tovu file uses the chat re-export. Changeset notes it.

## `packages/chat/src/react/surfaces.tsx` (full)
```tsx
/**
 * @file Chat's rich-surface port: the implementations a chat card renders through but must not
 * import (owner 2026-11-15, everything injected). Wire vocabulary (A2UI, MCP-UI resources) is NOT
 * here: it is plain data from @jini-ai/protocol. What is here renders or probes the host: the
 * MCP-UI sandbox iframe, the interactive component registry, the registry->catalog builder, and
 * WebMCP model-context detection. The host proves compatibility with `satisfies ChatSurfaces`.
 * The first `surfaces` value is kept: `useModelContext`-style slots must not change identity.
 */
import { createContext, useContext, useState, type ComponentType, type ReactNode } from 'react';
import type { Catalog, ComponentSpec } from '@jini-ai/protocol/a2ui';
import type { McpUiToolCallHandler } from '@jini-ai/protocol/mcp-ui';

/** Only the props chat passes to the MCP-UI iframe host. */
export interface McpUiHostProps {
  readonly title: string; readonly html: string; readonly sandboxProxyUrl: URL; readonly toolName?: string;
  readonly sessionKey?: string | number; readonly onToolCall?: McpUiToolCallHandler; readonly onOpenLink?: (url: string) => void;
  readonly initialHeight?: number; readonly maxHeight?: number | undefined;
}
/** A registry component chat can render inside an A2UI surface. */
export interface ChatSurfaceComponentEntry {
  readonly id: string; readonly propsSchema: ComponentSpec['propsSchema'];
  readonly Component: ComponentType<Record<string, unknown>>; readonly actionProp?: string;
}
export interface ChatSurfaceRegistry {
  list(required?: Record<string, never>, optional?: Record<string, never>): readonly ChatSurfaceComponentEntry[];
  resolveById(required: { id: string }, optional?: Record<string, never>): ChatSurfaceComponentEntry | null;
}
export interface AgentModelContextToolRegistration {
  readonly name: string; readonly title?: string; readonly description: string; readonly inputSchema: unknown;
  readonly execute: (args: Record<string, unknown>) => Promise<unknown>;
  readonly annotations?: { readonly readOnlyHint?: boolean; readonly untrustedContentHint?: boolean };
}
export interface AgentModelContextLike {
  registerTool(required: { tool: AgentModelContextToolRegistration }, options?: { readonly signal?: AbortSignal; readonly exposedTo?: readonly string[] }): Promise<void>;
  unregisterTool?(required: { name: string }, _optional?: Record<string, never>): void;
}
export interface ChatSurfaces {
  readonly mcpUi: { readonly Host: ComponentType<McpUiHostProps> };
  readonly interactiveUi: { readonly defaultRegistry: ChatSurfaceRegistry };
  readonly a2ui: {
    catalogFromRegistry(required: { registry: Pick<ChatSurfaceRegistry, 'list'>; catalogId: string }, optional?: { base?: Catalog }): Catalog;
  };
  readonly page: {
    getModelContext(required: { host: { candidates(required: Record<string, never>): readonly unknown[] } }, optional?: Record<string, never>): AgentModelContextLike | undefined;
  };
}

const ChatSurfacesContext = createContext<ChatSurfaces | null>(null);

export function ChatSurfacesProvider(required: { surfaces: ChatSurfaces; children: ReactNode }, _optional: Record<string, never> = {}) {
  const [surfaces] = useState(() => required.surfaces);
  return <ChatSurfacesContext.Provider value={surfaces}>{required.children}</ChatSurfacesContext.Provider>;
}
export function useChatSurfaces(): ChatSurfaces {
  const surfaces = useContext(ChatSurfacesContext);
  if (!surfaces) throw new Error('Chat MCP-UI and A2UI cards need <ChatSurfacesProvider surfaces={...}> above them '
    + '(or a ChatKitProvider whose kit has `surfaces`). Tovu: apps/<root>/src/integrations/jini-surfaces.ts.');
  return surfaces;
}
/** Same-name facade, so McpUiSurfaceCard changes only its import line. */
export function McpUiHost(props: McpUiHostProps) {
  const { Host } = useChatSurfaces().mcpUi;
  return <Host {...props} />;
}
```
CHECK: `McpUiHost` in ui is not `forwardRef` (it is `export function McpUiHost(props)`), so the facade needs no ref.
