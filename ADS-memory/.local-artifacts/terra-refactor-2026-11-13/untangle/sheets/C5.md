## Decisions
- **D1: the three functions**
  - **`omitEnvironmentKeys` is already pure.** It takes `env`/`keys` and does no I/O (`child-environment.ts:14-31`). It moves verbatim.
  - **`createCommandInvocation` can be made pure.** It reads only `process.platform` and `process.env` (`command.ts:74,90-91`). Core gets `planCommandInvocation(required: { command, platform, env }, optional: { args?, fallbackComSpec? })`. Its private helpers `quoteWindowsCommandArg` (46-54) and `buildCmdShimInvocation` (70-77) are copied verbatim, with one exception: `process.env.ComSpec` becomes `fallbackComSpec`. Platform keeps `createCommandInvocation` with its name and shape as a 1-line wrapper, so behavior is byte-identical. Consumers that already hold a process/platform port (daemon launch, agent-runtime, sidecar) call the pure function and need no port. `CommandInvocationPort` remains for hosts that want to swap it.
  - **`wellKnownUserToolchainBins` cannot be made pure.** It probes the filesystem (`existingChildBinDirs` → `existsSync`/`readdirSync`), calls `homedir()`, and uses `node:path` `join`, whose separator depends on the OS (`toolchain.ts:11-13,72-120`). It stays in platform. Its only consumer, agent-runtime, declares a local `ToolchainBinsPort` in R10. `resolveSystemProxyEnv` (which shells out) is treated the same way: a local agent-runtime port in R10.
- **D2: `isLoopbackHostname` becomes pure with identical semantics.** It uses `node:net` `isIP` only to test for strict dotted-quad IPv4 (`net/address.ts:42-51`). Core copies the body and replaces `isIP(x) === 4` with `STRICT_IPV4.test(x)`. That regex is Node's own `lib/internal/net.js` v4 pattern: `^(?:(?:25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9][0-9]|[0-9])\.){3}(?:25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9][0-9]|[0-9])$`. A parity test in platform checks it against `isIP` (tests §2). `classifyIpAddress` and `isPrivateAddress` keep `isIP` and stay in platform.
- **D3: `redactSecretShapes`, merged into the existing `core/redact`, with no C5 file.** diagnostics' `redactSecretShapes` cannot move to core. Its code-aware path needs the `js-tokens` runtime dependency (`diagnostics/src/core/secrets-only.ts:2,452`), and core keeps zero runtime dependencies. Core already has a full engine: `redactSecretsWithCounts({ input }, { redactPii: false, extraPatterns })` in `core/src/redact.ts`. Chat (`chat/src/core/user-text-redaction.ts`) is an R4 file, so the swap is an **R4 recipe**. Chat rewrites every `[REDACTED:*]` marker to `[token removed]` at the end, so marker names do not matter; the spans and the count do.
  ```ts
  // R4: user-text-redaction.ts
  import { redactSecretsWithCounts, type SecretRedactionPattern } from '@jini-ai/core';
  const CHAT_PATTERNS: readonly SecretRedactionPattern[] = [
    { name: 'chat_secret', regex: /(?<![A-Za-z0-9_-])sk-[A-Za-z0-9_-]{16,}/g },
    { name: 'chat_secret', regex: /(?<!\w)xox[baprs]-[A-Za-z0-9-]{16,}/g },          // keep the "-xoxb" why-comment
    // lookbehind keeps "Bearer " outside the span, as the old replacement did
    { name: 'chat_secret', regex: /(?<=\bBearer[ \t]+)(?!\[REDACTED)(?!(?:token|tokens|authentication|authorization|auth|scheme|credentials?)\b)[\w.~+\/=-]+/gi },
  ];
  const r = redactSecretsWithCounts({ input: protectedText }, { redactPii: false, extraPatterns: CHAT_PATTERNS });
  const base = { text: r.redacted, redactions: Object.values(r.counts).reduce((a, b) => a + b, 0) };
  ```
  **Gate:** all 5 chat redaction suites (`user-text-redaction{,.gaps,.path-boundaries}.test.ts`, `guard-user-text.test.ts`, `secret-question-answers.test.ts`) must pass **unchanged**. If any fails, STOP: the fallback is to inject `redactSecretShapes` through `UserTextRedactionOptions` (host binds diagnostics). Never edit the tests to pass.
- **D4: Node-typed option fields.** Core must not name `NodeJS.*`, `Buffer` or `typeof import('node:fs')`:
  - `RuntimePlatform` is a literal copy of `NodeJS.Platform`'s union. A platform typecheck test asserts that the two types are mutually assignable.
  - Blob bytes are a type parameter `Bytes extends Uint8Array = Uint8Array`, and platform aliases `BlobStorage = CoreBlobStorage<Buffer>`.
  - File-lock and writer filesystem handles are a `Filesystem` type parameter, so agent-plugins can type `FileLockPort<FilesystemPort>`.
- **D5: platform's manifest.** Platform depends on `@jini-ai/core: ^0.7.1`, and agent-plugins peers `^0.7.0`. Inside the workspace they link (`linkWorkspacePackages: true`). For publishing, platform needs the core minor that adds `./net`, `./contracts/blob` and `./contracts/runtime`, so its range moves to `workspace:^`. The coordinator applies that change, as a shared-manifest line, and the changeset bumps core minor and platform patch.
- **D6: what moves vs what stays.**
  - Single-consumer helpers stay in platform as consumer-local ports, per DESIGN §2.3: proxy-env, toolchain, devops `assertSafePublicUrl`/`createValidatingLookup`, and `readBootIdentity`/`ensureSpawnHelperExecutable`. The last ones sit in `*/node.ts` and `terminal.adapter.ts`, which move to the host preset under Q8 (R8, R11).
  - `GuardedReaderPort` goes in core as dispatched. Its value types already live in `core/filesystem`.
