## Decisions
1. **What moves:** all of `types.ts`, `token.ts` and `define-admin-module.ts` from `packages/admin/src/core/module/`. They are pure: types, one frozen-object factory, one `Object.freeze` identity. `createAdmin`, `AdminConfigError`, `AdminHostPorts`/`AdminOptions` and `controller-store.ts` stay in admin. `createAdmin` is the registry, and the registry stays in the package that receives the registration (DESIGN §2.2).
2. **`AdminInstance`, `AdminDescription`, `ScopedPorts` and `TabId` move too.** user-management's 8 `*.hooks.ts` files take `AdminInstance` as a type; leaving it in admin would keep 8 of its 12 admin edges.
3. **`adminPort` becomes core's `token<T>()`, keeping its name and its freeze.**
   - `AdminPortToken<T, Id>` becomes a type alias of core's `Token<T, Id>`. It is field-for-field identical: `token.ts:1-3` says it was a structural copy only because admin had no core dependency. Admin now depends on `@jini-ai/core` (non-optional), so the copy is stale.
   - `adminPort(...)` becomes `Object.freeze(token<T, Id>({ id }, { version }))`. Core's `token()` does not freeze; dropping the freeze would make admin tokens mutable (a silent behaviour change). The name stays because user-management, admin's own `*/ports.ts` and Tovu's module files call `adminPort`.
4. **New subpath** `@jini-ai/core/contracts/admin-module`, universal, file `core/src/contracts/admin-module.ts` (the `contracts/hosted-mcp.ts` pattern). Not added to the core root barrel.
5. **No shells:** the three admin files are deleted, and `admin/src/core/module/index.ts` stops exporting the moved names. `@jini-ai/admin/core/module` keeps only `createAdmin`, `AdminConfigError`, `AdminHostPorts`, `AdminOptions`. Admin's own 37 relative importers and every external importer are TSV rows.
