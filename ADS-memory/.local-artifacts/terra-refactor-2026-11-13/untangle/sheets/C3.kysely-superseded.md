## Decisions (read first)
- **D1, kysely (needs coordinator OK; STOP if refused).** `StorageKernel` is typed with `Kysely<DB>` and `RawBuilder<Row>` (`db/src/kernel/port.ts:1,75,85`). A repo body *is* a Kysely query, so the contract cannot be restated without kysely. Recommendation: core gets `kysely` as an **optional, type-only peer**:
  - `peerDependencies.kysely: "^0.29.6"`, `peerDependenciesMeta.kysely.optional: true`, `devDependencies.kysely: "^0.29.6"`.
  - Only `import type` from `kysely`, and only in `core/src/contracts/storage/kernel.ts`. No runtime byte is added.
  - C0's `L6-base-purity` needs one allow entry for this: `{ file: "packages/core/src/contracts/storage/kernel.ts", spec: "kysely", kind: "type" }`. The manifest check must accept an optional peer named `kysely`.
  - Every consumer that uses the kernel already declares kysely (chat, cms, commerce, daemon, plugins, db).
  - The rejected alternative is a module-augmentation map (`StorageQueryBuilders<DB>`, which db augments). It breaks for any consumer that does not load db's augmentation, so it is fragile.
- **D2, `listColumns` does not move.** It builds its query with kysely's runtime `sql` tag (`dialect.ts:1,159-181`), and core gets no runtime dependency. `ColumnInfo` (a type) moves. The function becomes `StorageCatalogPort` (below). db exports a binding `storageCatalog`. The only cross-package caller is cms `forms/sql/submission-ip-retention-repo.ts:21`, and R9 injects the port there.
- **D3, `executeCommand` stays in cms.** It is the CMS audited-write gateway. cms-forms only needs its *type* (`ports.ts:69`, `typeof import("@jini-ai/cms/core").executeCommand`). Core gets `ExecuteCommandFn`. cms proves the match with a type-level assignment.
- **D4, the SQLite openers become ports, not moves.** `sqliteKernel` (`db/kernel/sqlite/driver.ts:94`, which holds a module-scope `WeakMap` and `Map`) and `openSqliteConnection` (`db/sqlite/open.ts:64`) are I/O and state. Core gets their *types* plus `SqliteKernelPort` and `SqliteConnectionOpenerPort`.
- **D5, migrations follow the registration pattern.** `MigrationStep` and `MigrationContext` move. `runMigrations`, `MigrationOptions` (which carries the db-internal `Clock` and `LegacyLedgerMapping`) and `MigrationReport` stay in db. R6 changes commerce to export `COMMERCE_PAYMENTS_MIGRATIONS` and `COMMERCE_PAYMENTS_LEDGER_TABLE`; the host calls `runMigrations`.
- `JsonObject` in db (`row-values.ts:5`) is `Record<string, unknown>`. That is not core/primitives' `JsonObject`, which is recursive, so it moves under its own name.

### New code (full text)
```ts
// packages/core/src/contracts/storage/ports.ts
import type { ColumnInfo } from "./values.js";
import type { StorageKernel } from "./kernel.js";
import type { OpenSqliteConnectionOptions, SqliteClient, SqliteConnectionSource } from "./sqlite.js";

/** Catalog lookups that need the query builder at runtime (db implements: `storageCatalog`). */
export interface StorageCatalogPort {
  /** Columns in declaration order; empty when the table does not exist. */
  listColumns(required: { kernel: StorageKernel<unknown>; table: string }, optional?: Record<string, never>): Promise<ColumnInfo[]>;
}
/** Builds (and memoizes per client) the kernel over a connection the host opened. */
export interface SqliteKernelPort {
  kernelFor<DB>(required: { source: SqliteConnectionSource }, optional?: Record<string, never>): StorageKernel<DB>;
}
/** Opens a SQLite connection with the host's driver copy, applying pragmas and the recovery hook. */
export interface SqliteConnectionOpenerPort {
  open<Connection extends SqliteClient>(
    required: Pick<OpenSqliteConnectionOptions<Connection>, "filePath" | "open">,
    optional?: Pick<OpenSqliteConnectionOptions<Connection>, "recover" | "pragmas">,
  ): Connection;
}
```
