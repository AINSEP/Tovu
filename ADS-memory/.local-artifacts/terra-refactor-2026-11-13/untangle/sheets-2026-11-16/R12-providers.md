## The pattern (same in every sub-sheet)
1. **Types:** create `<provider>/contract.ts` and copy, field for field, only the type members the provider reads or returns. Header comment: "Structural copy of the `<domain>` provider port; the host proves the fit with `satisfies`. A plugin cannot import the domain package." Precedent to read first: the meilisearch agent-plugin's byte-identical copy and its test (`rg -l "byte-identical" packages/agent-plugins`).
2. **Helper values come through the context the domain already hands the provider.** Before designing anything, read the domain's context type and search for an existing owner (lesson 9).
3. **Fit is proven twice:** (a) the two-way drift guard of step 4 (there is no Tovu `satisfies` line: providers are packed artifacts, header above); (b) a type-level test **in the domain package** is not possible (the domain cannot import the provider), so (b) is the domain's conformance suite run by the host or by `packages/integration-tests` (G-TESTS T4).
4. **Drift guard (both directions, lesson 24):** `packages/integration-tests/src/provider-contracts.typecheck.ts` asserts `ProviderLocal extends Domain` **and** `Domain extends ProviderLocal` for the copied members. `packages/integration-tests` is created by **G-TESTS setup in wave 1** (Opus review B14; revision 2 wrongly said T0, wave 3). R12c (wave 2) and R12b (wave 3) write their halves there directly. R12a runs in wave 1 **in parallel** with G-TESTS setup, so its payments half goes to `examples/neutral-host/src/provider-contracts.typecheck.ts` (a Jini host that already imports both sides), and R12c's first commit moves it into `packages/integration-tests/src/` beside its own half (`git mv`, no assertion edits).
