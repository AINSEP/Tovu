**Providers are packed artifacts initialized by the existing provider host; there is no second assembly path.** `plugins/src/host/provider-host.ts:226` calls `provider.factory(input.input, { context: contract.context, ...factoryOptions })`: the domain's **contract registration** supplies `context` (`:16`), the host supplies `factoryOptions` (Tovu `composition/provider-plugins.ts:383`), and the entry (`payments-stripe/index.ts:13` `createStripeProvider(_required, _optional)`) is built by `provider-plugins/scripts/build.ts` and loaded as an artifact (`package.json:58`). Helper values therefore arrive as **`optional.context.<helpers>`**, put there by the domain that owns them, where it defines its provider contract. No sheet adds a Tovu `…Provider satisfies …` assembly file.

## The pattern (same in every sub-sheet)
1. **Types:** create `<provider>/contract.ts` and copy, field for field, only the type members the provider reads or returns. Header comment: "Structural copy of the `<domain>` provider port; the host proves the fit with `satisfies`. A plugin cannot import the domain package." Precedent to read first: the meilisearch agent-plugin's byte-identical copy and its test (`rg -l "byte-identical" packages/agent-plugins`).
2. **Helper values come through the context the domain already hands the provider.** Before designing anything, read the domain's context type and search for an existing owner (lesson 9).
3. **Fit is proven twice:** (a) host `satisfies` line in the Tovu file; (b) a type-level test **in the domain package** is not possible (the domain cannot import the provider), so (b) is the domain's conformance suite run by the host or by `packages/integration-tests` (G-TESTS T4).
4. **Drift guard (both directions, lesson 24):** `packages/integration-tests/src/provider-contracts.typecheck.ts` asserts `ProviderLocal extends Domain` **and** `Domain extends ProviderLocal` for the copied members. `packages/integration-tests` does not exist on merge-a (G-TESTS T0 creates it, wave 3): until then the file lives in `examples/neutral-host/src/` (a Jini host that already imports both sides), and G-TESTS T4 moves it.

They fail if a helper call is dropped or its arguments reordered.

## R12b: analytics-posthog
- `consent-adapter.ts:5` `purgeStorage` (value from `@jini-ai/cookie-consent/client`) — **browser boundary (judge finding 7, lesson 28).** The consent adapter is a separately delivered browser module: `provider-plugins/scripts/build.ts:104` emits it, `consent.ts:83` hands the browser its URL and a serializable config, and the module default-exports an already-created adapter (`consent-adapter.ts:202`). cookie-consent's **browser runtime** imports it (`cookie-consent/src/client/runtime.ts:55,180`: `importModule(src).then(m => m.default)`). A server-side binding cannot reach it. The injection point is that runtime: it owns `purgeStorage`, so it passes it on every adapter call that may purge: `adapter.onState({ state, storage: { purge: purgeStorage } })` (add the `storage` field to the `ConsentAdapter.onState` required type in cookie-consent's contract; adding a field only; update the runtime's call sites: `rg -n "onState\(" packages/cookie-consent/src/client`). The PostHog adapter's `onState` (`:159`) calls `required.storage.purge(…)` with today's arguments; `revoke` (`:182`) keeps delegating to the consent client. Privacy tests first, **against the built browser artifact** in jsdom (build, then `import()` the emitted file): (1) initial state off → this provider's cookies and local keys are purged and no client starts; (2) full → anonymous → purged once, with the same prefixes as before (characterize on old code); (3) revocation → the consent client's purge runs and the adapter stops. Each fails if the purge call is dropped or bound to the wrong state.
- `consent-adapter.ts:6`, `consent.ts:5` types → `analytics-posthog/contract.ts`: `ConsentAdapter`, `ConsentState`, `Revoker`, `StoragePrefixes`, `LazyAdapter`, `RawContribution`.
- `browser.ts:2`, `consent.ts:6`, `posthog.ts:23` (`BrowserAnalyticsContribution`, `ProductAnalyticsAdapter`, `ProductAnalyticsPort`): C12-OBS moves these to `@jini-ai/core/contracts/observability`; after it lands this is a repoint (applier rows are in `C12-OBS.repoint.tsv`). **Do not restate them here.** Precondition command: `rg -n "ProductAnalyticsPort" packages/core/src/contracts/observability` → hit; a miss is a **STOP** for the analytics half (do the cookie-consent half and report PARTIAL).
