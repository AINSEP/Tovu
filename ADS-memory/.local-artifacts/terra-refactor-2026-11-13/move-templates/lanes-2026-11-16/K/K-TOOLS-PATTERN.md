## Split
- catalog file -> MOVE whole. `<X>ToolDeps`, `<x>DerivedRisk`, view mappers, handlers, the model-facing rule list -> MOVE.
- `contribute<X>Tools`, the host `build<X>Registrations` (identity rule), the metadata import, the default-surfaces expression and every host port value -> STAY in Tovu `<feature>/tool-registrations.ts` (a binding of about 40-70 lines; it exports `contribute<X>Tools`, `build<X>Registrations` and the host `<X>ToolDeps`, nothing else; no `export ... from` of a Jini name).
- Every import of the Tovu file is classified in the sheet's BINDINGS table as one of: `own` (already this Jini package: rewrite to the leaf file), `core` (allowed as is), `port` (becomes a typed field of `<X>ToolDeps`; the sheet gives the type and the value Tovu passes), `structural` (type-only import of another package: a local interface with ONLY the members the handlers call, same member names/argument objects/returns, Tovu passes the real object unchanged), `host` (stays in the binding; this includes the daemon/platform imports of the default-surfaces expression, which stays as the default of the Tovu `build<X>Registrations`). An import with no row = STOP. (Revision 2's `delete` class is gone: deleting the default would force edits to every test that calls the builder without `surfaces`.)
- Approval-wrapped tools: Jini takes `deps.approvalHandler` typed as a local generic interface copied from the real signature above, with `describe` returning a local `<X>ApprovalDescription` holding only the fields the handler sets. If a `describe`/`dialog` body reads host wording (`approvalText`, locale, a Tovu import), that callback is NOT moved: it becomes `deps.describe<Tool>` and its body stays byte for byte in the Tovu binding. Tovu's `HumanConfirmSpec` must accept the local description type; the S4 typecheck proves it (mismatch = STOP, do not cast).
