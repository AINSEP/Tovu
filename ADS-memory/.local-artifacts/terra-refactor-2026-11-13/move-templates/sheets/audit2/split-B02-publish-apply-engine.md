## Design decisions made here (executor makes none)
1. Host policy that is data (denied table names, denied file roots, column pattern, limits, secret scanner) is a `BackstopPolicyConfig` value injected through `policy` in the `required` object of every policy function; Tovu keeps the lists in `features/publish-content/backstop-policy.ts` (reduced) and exports one `TOVU_BACKSTOP_POLICY` constant it passes at its own call sites.
2. Secret scanning/redaction are ports (`scanForSecrets`, `redact`), never imports: cms may import only itself + core + protocol, and the redaction/scanner owners are `@jini-ai/diagnostics` / Tovu webhooks.
3. `console.warn` in `backstop-preview.ts` becomes a `report` port (rule 7); Tovu binds `console.warn` + `describeErrorForLog` (this keeps the redaction in the host).
4. `PluginHookFailedError` (Tovu `contracts/core/plugin-hook-failed-error.ts`, a re-export of `@jini-ai/plugins/host`) cannot be imported by cms: the apply loop takes `markRefusedItem?: (required: { error: unknown; itemKey: string | null }) => unknown` (default: returns `error` unchanged); Tovu binds the `new PluginHookFailedError(..., { refusedItemRef })` wrapping.
5. The gated-mutation ceremony's `planHashOf` and `resolveActorClassIdentity` stay Tovu bindings (`contracts/core/gated-mutations/composition.ts`, shared by three ceremonies) and are injected as `planHashOf` / `resolveActorClassIdentity` fields of `BuildPublishContentImportHooksInput`. `GatedMutationHooks` is imported from `@jini-ai/core/gated-mutations` (exists, `packages/core/src/gated-mutations/gateway.ts:18`).
6. `apply-loop.ts` is NOT moved as-is: `applyReport` is a ~375-line method and `applyOneRow` a ~240-line function with five nested closures. Jini forbids functions > 50 lines / complexity > 10 and no exemption exists, so S5a flattens them in Tovu first (behaviour-preserving, guarded by the existing apply-loop tests), then S5b moves the result.
