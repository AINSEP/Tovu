## Design decisions made here (executor makes none)
1. **Peer domain vs vault binding.** The domain (errors, `PublishContentPeerRecord`, `PublishContentPeerSummary`, `PublishContentPeerRepoPort`, read/write deps, validation helpers, create/update/list/get/delete services, `InMemoryPublishContentPeerRepo`, connected-destination select/save/remove) moves. The vault-backed repository and its Tovu vault kind (`peerKinds`, `peerScope` with `ownerKey: "tovu"`, `peerVault`, `VaultPublishContentPeerRepo`, `resolvePeerCredential`, `credentialTokenHint`) stay in Tovu (`features/publish-content/peer-vault-repo.ts`, NEW, ~150 lines) because they bind Tovu's vault kind and the platform `SecretsVaultService`; Tovu's file `implements` the Jini `PublishContentPeerRepoPort`.
2. **Product wording is a value.** The five "is it a Tovu instance?" / "an older Tovu" strings in peer-transport (L282, L322, L410, L426 plus peer-url.ts L7/L22/L77/L85 doc text) take `productName: string` through `PeerCallDeps` (Tovu passes `"Tovu"`); wording is otherwise byte-identical (`a ${productName} instance`, `an older ${productName}`). Tests moved to Jini use `productName: "Peer"` and expectations are rewritten accordingly in the same commit; the Tovu test copies that assert the Tovu wording stay in Tovu (see tests).
3. **Egress refusal** is a port: `describeEgressRefusal?: (required: { err: unknown; hostname: string }) => string | null` (returns the host's full sentence for a refusal error, `null` when `err` is not a refusal). Tovu binds `err instanceof EgressRefusedError ? \`${err.callerSafeMessage}. '${hostname}' resolves to a private address ... (TOVU_PUBLISH_CONTENT_DEV_HOSTS ...)\` : null` — the env var name never enters Jini (rule 8). `toTransportError` calls the port; absent = treated as unreachable.
4. **Redaction/log** ports as in B02: `redact: (required: { text: string }) => string`, `report: (required: { message: string; error: unknown }) => void` (peer-transport L618 `console.warn`).
5. **History write** (`peer-transport.ts` L611, `kind: "tovu-peer"`, `PublishHistoryStore`): narrow port `recordRemoteApply?: (required: { target: string; url: string; trigger: string; summary: ... }) => Promise<void>`; Tovu binds the existing `PublishHistoryStore.record` call and keeps the literal `"tovu-peer"` kind (saved history rows read it: wire/data value, NOT renamed).
6. Functions over the size limit (declaration spans incl. comments: `callPeer` L235-292, `pushBundleToPeer` L487-557; `executePeerImport` L582-624, `pullBlobsFromPeer` L757-797, `fetchVerifiedPeerBlob` L852-879 are shorter): P1 must split `callPeer` and `pushBundleToPeer` (Opus draft; boundaries: request building / send+classify / JSON parse for `callPeer`; probe+trim / upload / confirm for `pushBundleToPeer`); the others are within 50 non-blank lines (confirm with eslint, split if not).
