### Cross-cutting: over-redacted model-facing errors (78 failures, through 11-10)

- `Call [redacted] with {}`: the status tool the publish error tells the model to call (6).

## Structural issues, ranked by failures each fix would remove

Estimates are failures per 3 weeks at today's mix (post-11-03 rate where the class changed).

1. **Two-tier tool surface: typed direct tools (≤64), plus `execute_[readonly_]delegated_tool`, plus `search_tools`/`describe_tool`, plus plugin MCP tools.** The model has to guess whether a name is direct, gateway-only, read-only, a namespace or a plugin tool. Classes: unknown tool 68, direct call to a gateway-only tool 12, read-only gateway refusal 11, external-plugin describe 404s; it also drives some Chrome fallback.
   *Smallest fix:* (a) one gateway that accepts any registered id and routes read vs write itself; keep the read-only wrapper as an alias only. (b) Resolve namespace calls: `content_read` + `{resource|type|entity|kind:X}` → `content_read.X`. (c) Unknown id → **404 `UNKNOWN_TOOL`** with did-you-mean, never 403 "denied". (d) Every tool named in guidance or refusal text (`load_agent_plugin`, `credential_save`, `agent_plugin_connect`, `plugins_set_enabled`) is pinned into the direct set; a lint fails when guidance names a tool that is not direct. (e) `describe_tool` of `mcp__<plugin>__x` answers "this is an external plugin tool; call it directly".
   **≈90 removed.**
2. **Model-facing error redaction strips recovery identifiers.** Pass the full registry id list as `diagnosticToolIds` on every daemon error path. Exempt schema property names in "Declared inputs" lines, slugs with letter+digit segments, and execution/job UUIDs (not secrets). **≈78 errors become actionable**; this cuts retries rather than first failures.
3. **No progress to the CLI during long or human waits.** Claude Code aborts any MCP call silent for 300 s. Send MCP `notifications/progress` every 30 s while a call waits on a card or job, or stage a per-server `timeout` for `jini` in the generated MCP config. **5–13 removed**, and it stops lost approvals and orphaned OAuth flows.
4. **Error envelope is not guaranteed.** Never emit a bare `HTTP 500`: include an error id, the first line of a non-JSON body, and "service restarting, retry" when the daemon/API is down (503). **≈40** become diagnosable; the cause of the 11-09 storm is still unknown.
5. **Batch semantics for same-target items.** Group batch items by `(themeId, path)` and apply them in order against the bytes the previous item produced. Pin once per file, not once per item. Reword the message to "this file changed since it was read". **≈21 removed.**
6. **Strict validation where clamping or helping is safe.** Clamp `read_tool_result.limit` to 8000. Treat `theme_list_files` without `themeId` as `theme_list`. Add a `sourceId` alias on `theme_duplicate`. Give `pages_read_html` a not-found hint for `/`/`home`. **≈35 removed.**
7. **Screenshot deadline.** Make the 20 s render deadline adaptive, or return a "best effort" capture of whatever rendered with a warning instead of failing. **≈20 removed**, plus fewer Chrome fallbacks (Chrome alone is 192 failures).
8. **Two sources of truth for "read-only".** Derive the gateway's read-only check from the same field as `approval.class`, or rename/redescribe tools that mutate (`external_mcp_get_admissions`). **≈11 removed** (covered by #1a if that lands).
9. **Product decision, not a fix:** site agents drive the owner's real Chrome (4,175 calls in 3 weeks, 192 failures, mostly tab-group collisions with other sessions). Options: give site runs their own tab group per run id, or prefer `web_screenshot_page` + `page.navigate` and keep Chrome for owner-asked checks only.
