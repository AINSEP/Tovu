## (a) One-paragraph recommended architecture
To serve all five audiences simultaneously, Tovu must adopt a **Strict Logic-Less Server Core with Unrestricted Client Islands** architecture. A single unified environment cannot securely render untrusted server code while simultaneously allowing the expressiveness developers want. Therefore, you must split the rendering plane. The server-side rendering layer must use a purely logic-less, text-substitution template engine operating within a strictly typed data context, ensuring absolute safety for untrusted marketplace themes (Audiences 1 & 4) and providing a predictable, standardized generation target for AI (Audience 5). To support developers building premium, animated sites (Audience 3), the theme manifest must allow the inclusion of arbitrary client-side CSS and JavaScript bundles. Heavy libraries like GSAP, Framer Motion, or custom interactions are shipped entirely to the client, executing purely in the user's browser sandbox and targeting the DOM generated by the server. This cleanly divorces safe, read-only server data rendering from unrestricted, browser-sandboxed visual execution. Content integration (TipTap JSON) is handled entirely by the server core prior to template evaluation, passed into the templates via a safe, pre-registered helper component that outputs sanitized HTML, preventing theme authors from needing to parse complex ASTs.

**On Type Safety (Q6):** Compile-time type-checking of the templates themselves matters surprisingly little for this specific product's success, which is why Liquid outranks JSX here. The stability of the system comes from the strictly typed TypeScript core generating the JSON context *before* handing it to the template. While JSX provides perfect end-to-end TS safety, it requires a build step and opens severe server-side execution vulnerabilities for untrusted code. Logic-less templates fail gracefully and are easily generated by AI without TS compilers.

## (c) The single best default engine
**LiquidJS** is the single best default engine for Tovu. It inherently enforces a logic-less paradigm, making it trivially safe to execute untrusted third-party code without requiring complex, heavy VM isolation (unlike EJS, Eta, or JSX which can be easily weaponized to exploit Node's execution context). It is the industry standard for commerce and CMS platforms (Shopify, Jekyll), meaning human developers, designers, and AI models all understand its syntax fluently. It provides precisely the right amount of expressiveness for layout control through secure, extensible tags, without crossing the line into arbitrary code execution.

## (d) Migration/evolution path
Tovu must ship the simple, safe option (LiquidJS) first to quickly establish a baseline marketplace, solve for non-developers, and ensure AI reliability. Once this foundation exists, you can add expressiveness without a rewrite by introducing a multi-engine manifest. A theme would simply declare `"engine": "astro"` or `"engine": "jsx"`. For local developers (Audience 3), Tovu would spawn a local bundler to compile these advanced themes. For the marketplace, Tovu would require these advanced themes to be pre-compiled and run within a strict WebAssembly (WASM) sandbox or an edge-isolate (like Deno Deploy). This provides a seamless migration path: the core data layer remains identical, backwards compatibility for Liquid themes is maintained forever, but you unlock world-class developer experiences as a premium tier once you have the engineering resources to build the secure WASM/Isolate execution boundary.

## (e) Top 3 risks or warnings
1. **DO NOT attempt to sanitize or sandbox JS-based engines (EJS, Eta, Next, raw JSX) yourself.** Untrusted templates running `Object.constructor`, prototype pollution attacks, or accessing the file system will immediately compromise your self-hosted users. If the engine allows raw JS execution, it is fundamentally incompatible with your "install from anyone safely" goal unless it runs in a heavy microVM (e.g., Firecracker), which destroys your "one portable folder" Node value proposition.
2. **DO NOT let the theme parse the TipTap JSON AST directly.** The template engine should never iterate through ProseMirror nodes. Tovu core must securely translate the JSON to standard HTML server-side, exposing a single, opaque helper to the theme (e.g., `{{ content | render_rich_text }}`). Pushing document AST rendering into the theme layer guarantees fragmented, buggy, and XSS-vulnerable output across the marketplace.
3. **DO NOT invent your own JSON block-tree template language.** You already have a JSON manifest for blocks, but extending this into a Turing-complete layout engine creates a proprietary nightmare. AI tools will hallucinate wildly on proprietary syntax, and developers will refuse to learn it. Adopt a ubiquitous standard immediately.
