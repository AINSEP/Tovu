# Move-to-Jini: Opus backlog

Everything from the old staged design that is NOT a drop-in repoint (Terra lane: `terra-lane.tsv`). 1,296 files / 233.6k lines. Exact file list, survey label and survey note per file: `opus-backlog.files.tsv` (columns `path loc feature action pkg subpath was_stage survey_note`; `was_stage` is the old stage it sat in, history only). Opus takes ONE feature at a time: read that feature's rows, check the code (survey labels are from Tovu c369798/a9c1184 and may be stale), decide, build, test what it changed.

## Rules every item follows (owner)
- Exported functions take `(required, optional = {})`; convert callers in the same change.
- Complexity: admin 9 cyclomatic / 9 cognitive, everywhere else 10/10. Functions <= 50 lines.
- Code moved into Jini never calls `console.*`: inject a report port; when it carries errors, the port gets the host's redaction, pinned by a failing leak test first.
- Why-comments move with the code (onto the Jini declaration when the Tovu copy goes).
- Behaviour change = failing test first. Jini changes are additive (no removed/renamed export Tovu still imports).
- Jini moved files import own-package code from the declaring leaf file, never the package barrel (that makes `index -> moved -> index`).
- Owner defaults: D1 Tovu stays on `link:jini` (one publish at the end); D2 WAIT: rows naming `@jini-ai/core` runtime (67 files) are not moved and not re-homed; D3 `commit-site` moves to site-backup.
