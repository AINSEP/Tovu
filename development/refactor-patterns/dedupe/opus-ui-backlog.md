# Opus UI backlog (dedupe d3): UI lifecycle consolidations

These items came out of the Terra prompts on 2026-11-13, after review d3r. Two of that review's finding classes repeated round one: a consolidation that bypassed an existing Jini owner, and new shared APIs that broke the `(requiredObj, optionalObj = {})` rule. The coordinator's decision: Terra keeps only mechanical jobs. Every effect, listener, timer or dialog lifecycle merge below is Opus work, done one feature at a time with Claude in Chrome looks, and a Codex check afterwards.

The old Terra recipes, which are the starting data and not the design, are at Tovu design-d3 `87d1293fb`: `dedupe-06` (J02, J35, J39, J48, T16J, T18J, T23J), `dedupe-10` (T11 Jini) and `dedupe-11` (T16 hooks, T18, T23, T11 Tovu).

Rules for each item:
- Before writing, search for and reuse the existing owner named in the row. Extend that owner with an optional option rather than adding a second lifecycle.
- New or changed APIs take `(required, optional = {})`, port operations included.
- Functions are at most 50 lines, with cyclomatic and cognitive complexity at most 10 (9/9 in Tovu `apps/admin`).
- Jini never imports Tovu.
- Why-comments move with their code.
- Write the failing or characterization test first.
- A Tovu change that needs a new Jini export waits for a Jini release (gate R1).
