# Split plan: apps/website/src/server/inbound/public-http/http/site/render.ts

## 1. Header
- Over: file 1664 counted (3703 raw), limit 500. No function is over 100 (largest: `pageShell` 34, `renderWidgetContactForm` 39). This is a file split only.
- Phase: **NOW, before the Tovu->Jini move.** Survey (canary b110-2) marks the doc renderer, media tags, widget IR and Page-embed wiring MOVE-AFTER (blocked on ~8 Tovu ports) to `@jini-ai/cms/widgets/html`; the shell/tiers/components STAY-PRODUCT. The split below cuts exactly along those lines, so the later move is a per-file move (render-safe-values, render-media, render-widgets, render-doc-tree, render-doc-page-html, render-post-body move; render.ts + render-site.ts stay).
- Executor: Opus/Fable. Run render.md BEFORE pages.md (pages.md imports the new render modules).
- Main job kept by render.ts = its own @file header: "walks the template's JSON block tree ... content doc nodes, slot nodes, component nodes". `renderSite`/`pageShell` (tier dispatch + document shell) move OUT to `render-site.ts`. Reason (load-bearing): the Liquid/Handlebars workers import `render.ts` (`liquid-render.ts:6-11`, `handlebars-render.ts:5`) and are capped by `__tests__/worker-import-graph.test.ts` `WORKER_MODULE_BUDGETS` (liquid 125, handlebars 165; history shows 130/173 failures on 10-30). Moving the shell out drops its worker-only-dead deps (font-links, theme/public-page-security-headers, token-aliases, product-root, site-chat-markup + `@jini-ai/chat/browser/lazy-loader`, `@jini-ai/cookie-consent/render`) from the worker graph FIRST; the 5 new worker-loaded modules come after. Expected net worker count: about -2. Not measurable without running the test; see Risks.
