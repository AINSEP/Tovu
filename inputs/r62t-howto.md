## 2. Missing guidance to add

These are the proposed assistant instructions. The sheets below name their destinations.

- **Build from a picture or URL.** “Use the reference for the page or section named. A request to migrate a whole site uses the import workflow. Preserve the site’s shared header, footer and theme unless the owner asks to change them. Use supplied assets and identify missing ones.”
- **Edit this page, section or homepage.** “Find the existing entry by exact address, or search by title and check the match. Read `/` to identify what serves the homepage. Edit the existing HTML section by its returned handle, or keep a rich-text entry in rich text. Preserve the URL, surrounding content and publication status unless the request changes them.”
- **Video, map or booking calendar.** “Use the YouTube block in rich text. For page HTML, discover an enabled embed that supports the exact provider, and use the owner’s real link and a labeled fallback. If only a link is supported, say so. Check playback or interaction where possible and keep the site’s consent settings.”
- **Use this image.** “Use a design attachment as a reference. If the owner wants that image displayed, promote the chat attachment to Media, or import the actual file or HTTPS asset. Use its saved public reference. Describe informative images in context and use empty alt text for decoration.”
- **Add this to the menu.** “Find the menu actually rendered by the active header or footer. Preserve its order and other items, use an entry link for an internal page, and verify it in the rendered menu. Check the theme’s menu marker when assigning a location has no effect.”
- **Add a contact form.** “Reuse or create a native form with supported fields, then place it on the requested page. Check that it renders and that submission is configured. An actual test submission requires authorization. Report notification setup separately from the ability to collect submissions.”
- **Improve SEO.** “Read current page metadata and site defaults. Edit only the requested entry fields and preserve a deliberate canonical URL. Check the rendered title, description and social metadata on the requested copy and report where it was verified.”
- **Preview, publish and hand back.** “Preview the draft by entry ID. Check the actual mobile and desktop render when available. After saving, say what changed, where to open it, whether it is a draft, scheduled, published here or verified live, and how to undo it when a matching recorded change exists. Name unfinished checks and failed items plainly.”

## 3. Incidents 2 and 3

### 2. YouTube missing in Page Preview

**The isolation is confirmed. The playback cause remains unconfirmed.** Both Page Preview branches use the authenticated template-preview route. Their outer frames set `sandbox` and `referrerPolicy="no-referrer"`. The route applies a second sandbox through the response CSP. Adding `allow-same-origin` to the iframe alone would leave the CSP restriction in place. Adding it to both would give authored scripts the admin origin that the sandbox deliberately isolates. See `apps/admin/src/features/pages/PageEditor.tsx:1386–1423`, `rules.ts:550–564`, and `apps/website/src/server/inbound/admin-http/routes/posts/template-preview.ts:174–178,218–221`.

There are two distinct failures to test. If the Preview response lacks the player, trace the saved body and embed path. Authored Page HTML and raw widget HTML have different handling, and the rich-text renderer emits its own `youtube-nocookie.com` iframe. If the player is in the response, inspect the nested request, including its referrer, and the player’s error. The outer frame’s referrer setting alone does not establish what the nested player receives. See `apps/website/src/server/inbound/public-http/http/site/render/post-body.ts:83–91` and `render/doc/nodes-media.ts:168–181`.

**N1, test first.** Open a saved Page and a pending edit containing the same known embeddable video. Assert the player is present in each Preview response, then capture the nested request and playback outcome in a browser. Compare with the public render. Fix the first divergence. If the request lacks the referrer the player requires, test an origin-only policy scoped to the supported player while retaining both admin sandboxes. If the fixture proves the inherited sandbox prevents playback, the smallest safe owner-facing fix is a labeled watch link in Preview. In-preview playback would need an isolated preview origin.

### 3. Assistant save and stale open editor

**The stale-version conflict is real. The pinned build already refreshes the normal clean, same-tab flow.** The Assistant Dock publishes refresh on tool results and run finish. Both editors subscribe and re-read. A clean, idle editor applies the new version. A dirty editor gets a choice, and the Interactive tab counts as potentially dirty because typed canvas text can still be buffered. The bus is in-process, so another tab cannot hear it. A refresh settling during a save is ignored. A genuinely stale save still reaches **Save anyway**, which replaces the other saved version. See `apps/admin/src/components/AssistantDock/hooks/messages-change.hooks.ts:150–168`, `apps/admin/src/lib/content-refresh-bus.ts:48–58,76–84`, `apps/admin/src/features/pages/hooks/use-page-editor.hooks.ts:961–971`, `apps/admin/src/features/posts/hooks/use-post-editor.hooks.ts:840–850`, `apps/admin/src/lib/external-entry-refresh.ts:55–66`, and `apps/admin/src/features/posts/editor/notices/PostVersionConflictBanner.tsx:38–59`.

**N2, test first.** Cover clean same-tab refresh as a control. Reproduce stale Save after an assistant write in another tab and a refresh that settles while Save is pending. For the first, recheck through the existing hook on focus. For the second, recheck once Save settles. In both editors, assert that clean editors advance to the new version, dirty editors retain typed text and their choice, and normal Save never overwrites the assistant’s version. Cover pending canvas text and paused autosave. Give the stale-save banner a direct **Load latest** action with its discard consequence, and label the deliberate overwrite **Replace their version**.

## 5. Owner decisions

- **Should a migration ever move the current homepage automatically?** I recommend staging always and showing the exact homepage, menu and theme changes on one approval card for the switch.
- **What should happen when someone asks for a draft of edits to a page already live?** I recommend previewing the proposed body without saving it and saying where it exists. A separately saved draft of a live page needs a product decision about how it later replaces the published version.
- **Does video need to play inside the editor?** I recommend shipping the watch-link fallback first if playback requires weakening the current preview isolation. Prioritize an isolated preview origin if in-editor playback is a product requirement.
