## 2. Problems (the four the brief named, plus three found)
1. **Provider loading drags the plugin-runtime binding** (1.2, 1.3). The loader needs Tovu's plugin-host binding because Jini's `discoverPlugins` takes `ManifestHostPorts & { tierPolicy }` (`packages/plugins/src/host/node/discovery.ts:40-43`, `host/ports.ts:35-43`) and `loadPlugin` takes `pluginSdkBinding`, `verifyDigest`, `tierPolicy` (`host/node/loader.ts:68-92`). Discovery calls `declarativeContentTypes.validateManifest` (`host/manifest.ts:491`). A desktop-only binding would be a second owner of plugin admission (lesson 31): rejected.
2. **Host signals need `bundledContributionSources` + `RETIRED_BUNDLED_AGENT_PLUGINS`**: the retired filter is behaviour (stale retired folders never contribute). The other 150 lines of `bundled-catalog.ts` are not needed.
3. **`bundledAgentPluginsDir` must stay lazy**: its root may only be computed when the env var is unset, and today the read happens inside `resolveBundledHostSignals`'s `try` (1.4).
4. **The `stage` script must survive**; only its second half goes.
5. (found) **Type re-export shell** `export type { ProductConsent, ProductTelemetry }` at website `product-telemetry.ts:19`; two desktop tests read types through it. Repoint to `@tovu/contracts/product-telemetry`; the line itself stays until its website importers are repointed (S4: listed, not widened).
6. (found) **Desktop dependency closure** (1.7): six new runtime packages must be declared by `apps/desktop/package.json`, or the packaged main fails with `ERR_MODULE_NOT_FOUND` only after packaging.
7. (found) **`observability-export` needs `resolveRuntimeMode`** (`runtime-mode.ts`, pure, 33 importers): host-shared may not import the website, so the rule must live in `@tovu/contracts` first.
