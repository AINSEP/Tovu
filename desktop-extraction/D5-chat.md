- So D5 **does not edit `desktop-agent.ts`** beyond import repoints, and starts when daemon R7-G1 and R8b are merged into BASE. **Express stays** (judge finding 8): R7 mounts the converted routes through a Node dispatcher and keeps the host's middleware and mount positions; it does not remove the host framework, and the desktop host owns parsing and authorization around those routes (`desktop-agent.ts:34,366`, middleware `:360-380`). The start condition is therefore: `git log --oneline BASE -- apps/desktop/src/desktop-agent.ts` shows the R7-G1 and R8b commits (name them in the report) and `npm --prefix apps/desktop test` is green on BASE. Removing Express from the desktop is not planned here; if the owner wants it, it is its own host migration with parser, authorization, error and socket tests.
- The survey's "`desktop-agent.ts:213-218` resolves `@jini-ai/core` from the daemon's location" hack: still present in the reading tree at `desktop-agent.ts:219-221` (`import.meta.resolve("@jini-ai/daemon")`, `createRequire(daemonEntry).resolve("@jini-ai/core")`, then `await import(...)`), with a second `import.meta.resolve("@jini-ai/mcp")` at `:238`. - **Lesson 14 and 18 (streaming and cancellation), each a test that fails on the named break:** events for a run arrive on one push channel shared by every run: the transport must drop an event whose run or subscription id is not its own (two concurrent runs, interleaved events); after `stopRun` resolves no further event reaches the consumer even if the main side sends one late; unsubscribe removes the listener (fake `subscribe` counts live listeners: 0 after close, after error, after stop); a reattach replays from the cursor without duplicating the event at the cursor; `subscriptionRandomPart` takes its entropy as an injected port (it does today: `SubscriptionEntropy`): pin it in tests.

## D5b: serving side and conversation store (Jini + Tovu pair; ~200k; proof T, then E and **P**)

1. **Store contract first — the whole of it (judge finding 10).** `workspace-conversation-store.ts` owns two data families in one persisted document under one write lock: conversations (list, rename, delete, save message) **and the tool-gap audit** (`appendToolGap`, `listToolGaps` `:27-28`, its decoding, retention, and the preservation of audit metadata on every conversation write, `:90-116`), read by `desktop-agent.ts:348-355,390-398`. Step 0 writes the complete method list and the persisted document shape (every top-level key) into the report. **The store does not move in D5b**: moving the file would make `chat` import daemon audit types (forbidden), and replacing it with `@jini-ai/chat`'s store on the conversation methods alone would drop the audit family. D5b moves only the serving core and passes the existing Tovu store in through a typed port. Whether `chat` gets a store that can carry a host-owned extra section under the same lock is INDEX OD-13 (a design, with an N-1 fixture of today's document and automatic handling of existing files).
2. Serving core: from `workspace-chat-ipc.ts` take the functions that turn a start/reattach/stop/status request into calls on a run lifecycle and push events to a sink (`EventSink`), as `createBridgeChatServing(required: { runs; store; sink }, optional)` in `packages/chat/src/server/bridge-serving.ts`. The 18 `ipcMain` registrations (through D1a's kit), `addresseeForStart`, the inventory and working-directory channels stay in Tovu.
3. **Security (class: IPC sender trust; cross-run access): characterize, do not add (judge finding 11).** Today reattach and stop address a run by its id with no sender-ownership rule (`workspace-chat-ipc.ts:172-181`), and the renderer relies on that: a pane is disposed and a later one reattaches (`renderer/workspace-chat-transport.ts:269-279,405-431`). Tests pin exactly that: reattach after the original sender is gone succeeds and receives events; stop by run id from the sites-home sender succeeds; the channel's sender gate (D1b2's inventory row) is unchanged. "Sender B cannot reattach or stop sender A's run" is **hardening with an undefined lifecycle** (who owns a run after window destruction, renderer reload, loss of the sender; what status and detach do): INDEX OD-11, decided and designed separately, not in D5b.
Proof P: `npm run smoke:packaged-chat` (the packaged-chat gate) on macOS; E as D5a.
