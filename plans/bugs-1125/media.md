## LF-1 — Chat attachment admission, staging, and delivery

**Bugs** `O1731`, `O1732`  
**BUILDER** SOL

**Root cause.** Tovu configures the 550 MiB per-turn cap but leaves the daemon’s total store capped at 200 MiB, so a single permitted 500 MiB video cannot register.  
Run start copies claimed files into the site boundary, then reads each full payload for MIME detection. BYOK and live input also hydrate full payloads through the owner reader, even when they will only return an unsupported-video notice.

**Anchors.** `apps/website/src/server/inbound/assistant/agent-daemon-scope-attachments.ts` and `byok-message-attachments.ts` remain Tovu adapters. `origin/codex/tv-w2all` replaces `apps/website/src/features/media/read-chat-attachment.ts` with `chat-attachment-reader-host.ts` in that directory, backed by Jini `packages/daemon/src/http/attachment-owner-read.ts` on `origin/codex/w3-r2allj`. The existing Jini owners for storage, staging, and delivery are `packages/daemon/src/http/disk-attachment-store.ts`, `attachment-staging.ts`, and `packages/daemon/src/attachment-content.ts`. The `tv-w3` snapshot of the scope adapter has the older `50 MiB × 2` batch rule. Reapply this sheet only after the merged host preserves the merge-23 500/550 MiB policy.

**Failing tests first.**

- Tovu `apps/website/src/server/inbound/assistant/__tests__/scope-attachment-limits.unit.test.ts`, or its successor if extraction removes it. **“A clean scope accepts a complete maximum-size composer batch.”** Open the real host store and register a sparse 500 MiB video and 50 MiB companion in one batch. Both register. One more byte in a separate batch gets the existing store-full refusal. Mutation `omit-scope-max-stored-bytes` removes only the host's total cap override.
- Tovu `agent-daemon-server.attachment-run-fields.unit.test.ts` and `byok-message-attachments.unit.test.ts` in the same directory. **“A video is sniffed from a prefix without reading its payload.”** Use a video header with a full-read spy that fails if called. CLI still gets the staged path and notice, BYOK gets the unsupported-video notice, and an admitted PNG still delivers its full, exact base64 pixels. Mutations `hydrate-staged-video` and `hydrate-byok-video` restore each full read independently.
- Jini `packages/daemon/src/http/__tests__/attachment-site-staging.test.ts`. **“Staging requests copy-on-write and keeps independent file identity.”** Assert the copy port receives `COPYFILE_FICLONE` and preserve the existing original/alias/cleanup assertions. Mutation `stage-with-plain-copy` drops the mode. In `attachment-owner-read.test.ts`, pin that a non-owner gets no prefix read and an over-cap native image gets no full read. Mutation `read-image-before-limit` moves the cap after the read.

**Exact fix.**

1. Set `maxStoredBytes: MAX_UPLOAD_BATCH_BYTES` in Tovu `openScopeAttachments`. Leave Jini defaults, count limits, retention, upload routing, and original claim semantics alone. A full store still refuses rather than evicts.
2. In Jini `attachment-content.ts`, expose `isNativeMessageImage({ mimeType }, _optional = {})` over the existing PNG/JPEG/GIF/WebP set and reuse it in `prepareMessageAttachments`. In Tovu `readStagedAttachment`, replace the path-only full reader with an injected descriptor reader. Read at most 64 KiB at offset zero, sniff bytes, and read the full payload from that same descriptor only for a native image when the runtime accepts images. Reject a native image above the ordinary 50 MiB ceiling before full read. Preserve notices and close the descriptor on every exit.
3. In Jini `attachment-owner-read.ts`, add a delivery read mode to `readChatAttachmentForOwner(required, optional = {})` with `selectRead({ prefix }, {}) => "prefix" | "full"` and `maxFullBytes`. Inject the positional prefix read on the verified handle for this mode. Leave existing `maxBytes` behavior unchanged for preview and promotion callers. Authenticate and verify identity first, take the prefix from the checked descriptor, and enforce `maxFullBytes` before any full read. Thread the mode through Tovu `readOwnerChatAttachment` and use it in `prepareByokMessageAttachments` with the same sniff and native-image predicate. `deliverRunUserMessage` keeps its existing unsupported result so a video can still follow the idle-delivery path.
4. In Jini `stageAttachmentClaim`, inject the copy operation with its production binding set to Node `copyFile` using `COPYFILE_FICLONE`. Keep staging location, modes, original record, alias registration, and cleanup order. Never hard-link. On filesystems that cannot clone, Node retains the current independent copy, so the extra disk peak remains there.

**Order and manual check.** Land the host cap independently, then the Jini reader changes with their Tovu bindings, then the staging change. In the packaged app, attach a 500 MiB `.mov` and a 50 MiB companion to a fresh site. Send via Local CLI, then repeat via BYOK. Confirm the CLI run names the accessible video, BYOK reports it as unsupported, a screenshot still arrives as pixels, and cancel/finish removes staged files. Measure run-start RSS and allocated disk separately. The planned non-image read is at most 64 KiB per attachment, exclusive of staging I/O.

## LF-2 — `files_copy` into Media uses the converting importer

**Bug** `c21-asset-transfer-no-conversion` (`O1718`)  
**BUILDER** SOL

**Root cause.** The Tovu media destination calls `persistImportedMedia` without the video conversion binding.  
The public `files_copy` route also caps inputs at 10,000,000 bytes, so a wiring-only fix cannot reach the real conversion threshold above 50 MiB. Its approval preparation additionally base64-encodes Media inputs even though they do not use that approval path.

**Anchors.** Tovu `apps/website/src/features/asset-transfer/asset-destinations.ts` → Jini `packages/cms/src/asset-transfer/asset-destinations.ts` on `origin/codex/w3-r2allj` and `r3-w1aj`/`r3-w1bj`. Its media branch calls `deps.media.persist`. Tovu `apps/website/src/features/asset-transfer/copy-tool.ts` → Jini `packages/cms/src/asset-transfer/copy-tool.ts` on `origin/codex/r2y-ext-w1j`, **not** on `w3-r2allj`. Tovu `apps/website/src/features/media-import/tool-registrations.ts` → Jini `packages/cms/src/media/site-import/tool-registrations.ts`, where `persistImportedMedia` calls `storage.upload`. Keep source adapters and production binding in Tovu `asset-sources.ts`, `server/runtime/composition/asset-tool-host.ts`, and `tool-catalog-manifest.ts`.

**Failing tests first.**

- Jini `packages/cms/src/asset-transfer/__tests__/copy-tool.test.ts`. **“One large video reaches Media without an approval payload.”** Drive the registered handler with one source just above the old 10 MB cap, sniff it as video, and assert the exact bytes and actor reach `media.persist` with no base64 work or approval call. The same-size non-video is refused before persistence. Mutations `copy-keeps-media-at-10mb` and `encode-media-approval-batch` restore the two old paths independently.
- Tovu `apps/website/src/server/runtime/composition/__tests__/asset-transfer-video-wiring.integration.test.ts` (new). **“The composed files_copy Media destination stores the original and links the web copy.”** Drive the production contributor with a real importer and injected transcoder. Assert that the original is present before the conversion call and remains after it, and that the converted MP4 links to it. Mutation `asset-persist-uses-bare-upload` binds the non-converting uploader. A test that only spies on `media.persist` does not catch this mutation.

**Exact fix.** Bind the existing `AssetDestinationDeps.media.persist` to `persistImportedMedia` with the same converting `MediaToolStoragePorts.upload` used by direct Media import. Pass that binding from `installResourceTools`, using its existing conversion ports and note sink. Keep the Jini `media.persist({ input, sourceUrl, actorId }, {})` signature unchanged and keep host conversion choices out of Jini.

In Jini `copy-tool.ts`, inject `mediaVideoMaxBytes` on `FilesCopyToolDeps`, with Tovu supplying its existing video cap. Apply it only to a single non-glob source copied into Media. Thread the selected byte ceiling through `prepare`, `readGroup`, and `readUrl` to the existing source ports. Before persistence, require a sniffed `video/*` type to use the larger allowance. Keep the current caps and aggregate rules for all other inputs and destinations. In `asset-destinations.ts`, have `approvalBatch` return before encoding unless the destination is `site` or `picked`. Update the `files_copy` catalog to state the narrow Media exception. Do not change theme policy or the image-transform tool.

**Order and manual check.** Land both extraction pieces first and verify the extracted importer still preserves merge-23’s conversion and video MIME policy. Then land the host binding and admission fix together. In packaged Tovu with FFmpeg available, use `files_copy` to import a non-web-safe video above 50 MiB into Media. Confirm the original remains downloadable and the linked H.264/AAC MP4 plays in the app. This sheet still uses bounded full-buffer copy input. It does not claim the streaming memory improvement in LF-3.

## LF-3 — Admin JSON upload ceiling and local-file import memory

**Bug** `O1733`  
**BUILDER** NEEDS-OPUS for the streamed local-video phase, which crosses guarded file I/O, blob persistence, and conversion. The JSON phase is independently buildable by SOL.

**Root cause.** The admin parser accepts a 700 MiB JSON body, but the base64 representation of a 500 MiB video cannot fit in a Node string.  
Local-file import avoids base64 but accumulates all guarded chunks and concatenates them. Conversion then reads the original blob into memory again.

**Anchors.** Tovu `apps/website/src/server/inbound/shared/json-body-parsers.ts`, `server/runtime/composition/modules/media.ts`, and `apps/admin/src/features/media/hooks/use-media.hooks.ts` remain host paths. `tv-w3` predates the 700 MiB route split, so use the merged branch’s parser and upload hooks. JSON route owners are already Jini `packages/cms/src/admin-http/routes/media/{upload,replace}.ts`. The local import handler moves from Tovu `apps/website/src/features/media-import/tool-registrations.ts` to Jini `packages/cms/src/media/site-import/tool-registrations.ts` on `w3-r2allj` and both `r3-w1*j` refs. `packages/core/src/contracts/site/media-tool-ports.ts` is the extracted port. Jini `packages/platform/src/fs/guarded-reader.ts`, `packages/cms/src/media/{media-service,ports,video-transcode}.ts`, and the blob adapters already own the underlying work.

**Phase A — Cap the JSON transport.**

- **Tests first.** Tovu `apps/website/src/server/inbound/shared/__tests__/json-body-parsers.test.ts`, **“Media POST and replace reject a body above the safe JSON ceiling before reading it.”** Use a declared-length probe and assert the existing JSON 413 response, with publish-content still at 75 MiB. Jini `packages/cms/src/admin-http/routes/media/__tests__/{upload,replace}.test.ts`, **“JSON payload one decoded byte over budget never reaches the writer.”** Inject a tiny cap and use padded data at the boundary. Admin `apps/admin/src/features/media/__tests__/use-media.hooks.unit.test.tsx`, **“An oversized video never reaches FileReader.”** Mutations `restore-700mb-parser`, `decode-before-json-size-check`, and `read-before-client-limit`.
- **Fix.** Set a 192 MiB decoded ceiling for admin base64 video, with a 257 MiB JSON ceiling including metadata headroom. Put the browser-safe policy in Jini `packages/core/src/contracts/site/media-upload-limits.ts` and use the same value in the Tovu parser, route bindings, and pre-FileReader size check. Add `assertBase64UploadSize({ value, limitBytes }, _optional = {})` beside the shared route error mapping. Count decoded length from encoded length and padding before allocation, and use the existing `MediaUploadSizeError` envelope. Call it from `decodeUploadPayload` and `parseReplacement` after the existing authorization gates. Preserve strict decoding, sniff-based limits and the 50 MiB ordinary and document ceilings. In admin `useMedia`, inject the file reader and surface the actual JSON limit through the existing upload error path. Do not lower the 500 MiB chat or non-JSON video limit.

**Phase B — Stream large local videos through storage and conversion.**

- **Tests first.** Jini `packages/cms/src/media/site-import/__tests__/tool-registrations.test.ts`, **“Large local video imports and converts without a whole-file read.”** Use a bounded chunk source, fail-on-call byte reader and blob `get`, and injected staged storage/conversion ports. Assert matching original bytes and hash, preserved provenance, original-before-derived ordering, and cleanup when streaming or conversion fails. In `packages/platform/src/fs/__tests__/guarded-reader.binary.test.ts`, **“The streamed reader refuses growth and closes the validated descriptor.”** Mutations `local-video-collects-chunks`, `conversion-reloads-original-buffer`, and `stream-ignores-byte-cap`.
- **Fix.** Add `withGuardedBinaryStream({ rootPath, relativePath, maxBytes, consume }, { signal } = {})` in `guarded-reader.ts`, using the existing containment, deny, and opened-descriptor checks. Give `consume` the validated length and a backpressured `AsyncIterable<Uint8Array>` with chunks at most 64 KiB. Refuse overrun and close in the existing ownership boundary. In extracted `createMediaImportLocalFileHandler`, inject `source.withLocalStream` and `storage.uploadStagedVideo` through `media-tool-ports.ts`. For inputs above the ordinary ceiling, sniff the prefix, refuse non-video, and stream the prefix plus remainder to a private spool while hashing. Keep the current byte path and chat previews for smaller files.
- In the Jini media service, use the completed spool’s hash and length with the existing blob lock, dedup, and blob-before-row/rendition ordering. Add the staged write to the blob adapters behind an injected port. Add a staged input/output path to `video-transcode.ts`, bound by Tovu `createMediaConversionPorts` to the FFmpeg adapter so neither the original nor the derivative must be a whole JS buffer. Keep original-on-conversion-failure, existing rendition/link cleanup, provenance, response shape, and conversion notification behavior. Bound input by the existing 500 MiB policy and output by the existing conversion budget. Release both spools on success, refusal, or cancellation. If the deployed blob adapter cannot consume the staged source without collecting it, stop this phase and report the missing adapter capability.

**Order and manual check.** Ship Phase A independently. Do not mark the local-memory half closed until Phase B passes through real storage and FFmpeg. In packaged Tovu, verify an oversized Media upload is refused before file encoding and a small upload still works. Then import a 500 MiB local `.mov` through `media_import_local_file`, check original hash and playback of the linked MP4, and repeat with cancellation. Record Node RSS, FFmpeg RSS, and spool disk separately. The 64 KiB chunk limit is a design bound, not a measured end-to-end RSS claim.
