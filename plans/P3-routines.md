## Design (kept simple)
One Jini SQLite routine store per site (site-private DB file), one `RoutineService` per **owned desktop site scope**. Each fire: Jini claims the due slot and advances `nextRunAt` in one transaction, Tovu creates a fresh owner conversation and starts an ordinary owner chat run through the normal acceptance path. Approvals use the existing run-bound card; the run waits; the Routines screen shows **Waiting for approval** and links to the conversation. Catch-up: on desktop start or wake, a routine whose stored `nextRunAt` is in the past fires **once**, flagged `catchUp: true`, then advances to the next future slot. No BYOK runs in the first release (owner question 3).
