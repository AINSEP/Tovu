## Priority 1 bug — admin "unauthenticated / logged out quickly"

Root cause (in `src/server/middleware/dev-auth.ts`):
1. **Sessions are an in-memory `Map`** (`const sessions = new Map(...)`, line ~22) that **resets on every server restart**. The dev server runs `tsx watch` (package.json `dev`), which **restarts on every file edit** → all sessions wiped → the admin's next `/api/admin/*` call 401s ("unauthenticated"). This is the "logged out quickly" symptom while developing. (Booting/killing the server for verification also wipes it.)
2. **The session cookie has no `Max-Age`/`Expires`** (line ~73) → it's a session cookie, dropped when the tab/browser closes.

Recommended fix (small, contained): replace the in-memory Map with a **stateless signed cookie** — cookie value = `base64url(payload).hmac`, payload `{userId, exp}`, verified with an HMAC secret (`TOVU_SESSION_SECRET`, dev default constant). No server-side store → survives `tsx watch` restarts; add `Max-Age` (e.g. 7d) so it survives tab close. Update `currentSession`/`registerAuthRoutes` accordingly; `logout` just clears the cookie. Alternative stopgap: persist the sessions Map to `content.db` or a file, and add `Max-Age`. (Cookie plumbing is otherwise fine: vite proxies `/api`→:3000 same-origin, `credentials: "same-origin"` in `apps/admin/src/lib/api.ts` works; SameSite=Lax OK.)
