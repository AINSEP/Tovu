Adapted from an original Open Design export ("relay" — an 8-page SaaS marketing + auth
site) generated by Leon's own design tooling, not derived from any third-party template
or product. Placeholder logos (NORTHWIND, FLUXPOINT, HARBOR CO., VELOCITY, GRIDWORKS,
STACKFORM) and the quoted testimonial are fictional, invented for the export.

Rebuilt here as Tovu's first `static`-tier (plain HTML/CSS/JS, no template language)
theme:

- `nav.html` and `footer.html` were factored out of the 8 page files, which shipped
  each with the nav/footer markup duplicated verbatim (confirmed via hash comparison —
  footer was byte-identical across 6 of 8 pages; the auth pages `signin`/`signup` use a
  lighter `footer-minimal.html` variant). Pages reference them via
  `data-embed-config='{"type":"partial","id":"nav"}'` /
  `data-embed-config='{"type":"partial","id":"footer"}'` (originally two attributes,
  `data-tovu-slot`/`data-nav-current`, consolidated onto the one JSON-valued marker
  attribute in `b7acc21`), rather than a template include directive — no executable
  code ships inside the theme.
- The brand mark's checkmark stroke was hardcoded `#08090b` (near-black) in the
  source, correct only against the dark-mode mark background. Changed to
  `stroke="var(--bg)"` so it reads correctly against the light-mode mark too — a real
  bug the light-mode port surfaced, not present in behavior before this theme had two
  modes.
- `tokens.json` (dark) is a straight port of `css/relay.css`'s `:root` block.
  `tokens.light.json` has no corresponding CSS in the source at all — only the
  `-light` reference screenshots — so it was built by **pixel-sampling
  `screenshots/index-light.png` directly** (Python/PIL, row-scanned for the darkest
  text pixel in the hero `h1` and lede paragraph, plus a saturation scan for the
  `.kicker` label's flat accent color — not the decorative hero glow, which is
  gradient art and not a real color swatch). `--bg`/`--fg`/`--muted`/`--accent` are
  directly measured; `--surface`/`--surface-2`/`--border`/`--accent-fg` have no
  isolated flat swatch anywhere in the export (every card/panel region in the
  screenshot has the decorative mesh gradient bleeding through it), so those are
  derived from the four measured anchors using the same step relationships as the
  dark token set.
  **Finding from the measurement:** light mode's neutrals are green-tinted
  (`--fg` `#09140f`: G=20 > R=9), not a re-lightened version of dark mode's blue-gray
  neutral (`oklch(96% 0.003 250)`, hue 250) — an early pass here guessed the same hue
  family as dark and was wrong; the two modes use different neutral hues, not just
  different lightness. `styles.css` itself needed no changes — it already reads only
  `var(--x)`, so one stylesheet serves both token sets.
- `preview/` and `screenshots/` are generated by `build-preview.mjs`, a small
  slot-and-token stitcher standing in for Tovu's real theme loader (the `static` tier
  is not wired into `src/features/theme/theme.ts` yet). Re-run it after editing
  `nav.html`, `footer.html`, `pages/*.html`, or either tokens file.
- **Live light/dark toggle added** (`js/theme-toggle.js`, sun/moon button in
  `nav.html`). Both token sets now ship in every page (`:root` = dark,
  `:root[data-theme="light"]` = light overrides), so the `<mode>` a preview page was
  built under only sets its *initial* state — the toggle switches between them
  client-side, persists the choice to `localStorage`, and the icon crossfades via CSS
  (`opacity`/`transform` transitions, not `display` toggling, since `display` can't
  animate).
- **Scroll-reveal animation added**, powered by a vendored copy of
  [Motion](https://motion.dev) (`js/vendor/motion.js`, v13.0.0, MIT — license text at
  `js/vendor/LICENSE.md`). Deliberately **vendored, not loaded from a CDN**: a
  `<script src="https://...">` pointed at a third party would mean the theme's own
  claim of being safe to install and self-hostable ("your content, your themes, your
  data, on your machine" — `tovu-official`'s own copy) stops being true the moment the
  CDN is blocked, offline, or compromised. The vendored file carries the same trust
  model as the theme's CSS: a static asset shipped with the theme, not a live
  third-party dependency. `js/reveal.js` calls Motion's `animate()`/`inView()`/
  `stagger()` on `[data-reveal]`-marked sections and, for repeating grids
  (`.feature-grid`, `.pricing-grid`, `.values-grid`, `.changelog-list`,
  `.photo-grid`), on every child automatically via `stagger()` — no per-card markup
  needed. Deliberately **no default `opacity: 0` in CSS**: the hidden-then-revealed
  state is applied entirely in JS, so a visitor with JS disabled sees normal, fully
  visible content rather than a page permanently stuck invisible. First pass here used
  hand-rolled `IntersectionObserver` + CSS transitions (~40 lines, zero dependencies);
  replaced with vendored Motion at the owner's explicit request for the larger
  animation vocabulary it unlocks (spring physics, gesture/layout animation later) —
  worth knowing this is a **139KB / 46KB-gzipped** dependency traded for that
  headroom, not a free upgrade.

The reference screenshots (`index.png` / `index-light.png` in the original export)
depict a visibly richer landing page than the shipped `index.html` — a product
screenshot panel, an AI-triage feature section, a stats row, a code sample, four named
testimonials, and a terminal-install CTA are all present in the PNG but absent from the
HTML/CSS/JS source. This port is faithful to the HTML/CSS/JS source only; the fuller
landing page shown in the reference screenshot was not reconstructed.

## Rebrand + generalization pass

Renamed "Relay" → "Basic" throughout (directory renamed `relay/` → `basic/`,
`theme.json` `id`/`name` updated to match rather than left to diverge from the
display name) and rewrote all copy from a CI/CD product to a generic
"premium themed websites" product — this theme is now itself a plausible
marketing site for Tovu's own theme offering. Added `pages/blog.html` (9th page,
`.blog-grid`/`.post-card` pattern, wired into the same nav/footer/reveal system as
every other page) and a CSS-only infinite-scroll logo carousel (`.logo-carousel`/
`.logo-track`, same 6 fictional company names as the original export — not
substituted for real companies).

**Hero animation: two iterations, both from direct owner feedback.** First pass used
`js/typewriter.js` (character-by-character reveal) on every page's H1. Owner feedback:
choppy specifically on the two-line homepage hero. Replaced that one instance with
`js/hero-intro.js` — "Beautiful websites," slides in from the left, "shipped in
minutes" from the right, via Motion's `animate()` (plain per-element `delay`, not
`stagger()` — `stagger()`'s returned function is meant to be handed to Motion
internally across one `animate()` call over an array of targets, not manually invoked
per element with `(i, total)`; verified against the vendored build's own `stagger=
function(t=.1,{startDelay,from,ease}={})` signature before using it either way).
Owner then asked for typewriter to be dropped everywhere in favor of the existing
`[data-reveal]` fade-in. `js/typewriter.js` was deleted entirely (not left as dead
code) once nothing referenced it.

**Two real CSS bugs found via the owner catching a live render as "awful" (not
caught by any earlier screenshot — see the capture-timing note below) — both fixed
and verified with real DOM measurements, not just re-read source:**
- `.blog-grid`'s last row rendered underneath the footer. Root cause: `.post-card` is
  a grid item that is *also* a flex column containing a `flex: 1` child (`p`) — grid
  items get an implicit `min-height: auto`, which makes the row's auto-track sizing
  and the flex child's "grow to fill available space" sizing mutually circular. Fixed
  with the standard mitigation, `min-height: 0` (+ `min-width: 0`) on `.post-card`.
  Verified via `getBoundingClientRect()` before/after: last card's `bottom` dropped
  from 2344px (311px past the grid's own `bottom` of 2033px) to exactly 2033px.
- The featured post card's title/excerpt rendered as narrow, awkwardly-wrapped
  vertical columns. Root cause: `.post-card.featured` sets `flex-direction: row`, and
  the tag/`h2`/`p`/meta were direct children — each became its *own* row item instead
  of one stacked text column beside the media. Fixed by wrapping them in a
  `.post-card-body` (`flex: 1; min-width: 0`) so the row has exactly two children:
  media (42%) and body.

**Screenshot-capture-timing lesson, paid for twice this session:** navigating and
screenshotting immediately (no wait) reliably catches `[data-reveal]` content
mid-animation (opacity ~0.05–0.3, well below its final `1`) — a rendering artifact,
not a bug, but indistinguishable from one in a still image. Fixed by waiting ~2.2s
after navigation before every screenshot in the final verification pass. The actual
layout bugs above were only found because a live, normally-viewed page (not a rushed
capture) was checked directly.

`build-preview.mjs` also gained a `rmSync(outDir, {recursive:true,force:true})` at
the top of `build()`: it previously only ever copied/wrote files it currently knows
about, so a deleted source file (this happened for real with `js/typewriter.js`)
would linger in `preview/` indefinitely as an orphan.

Mobile nav fix (pre-existing bug, not introduced this pass): `.main-nav` got
`display: none` below 640px and `main.js`'s `nav-toggle` click handler already
toggled an `.open` class, but no `.main-nav.open` CSS rule existed anywhere — the
"Menu" button did nothing. Added a proper dropdown-panel treatment for `.open`.
